# 의도: 11-23 구현의 남은 코드 3건 마무리

> 상태: 사용자가 2026-11-24 확정 (interview-me).
> 관련 문서: [이벤트-증거구간-검토-보관연장.md](이벤트-증거구간-검토-보관연장.md), [API §7](../../API/실전시험_감독_API.md), [상혁 기록 README](../../기술검증%20및%20개선/상혁/README.md)

## 목표 (Why)

11-23 에 구현한 감독 기능의 남은 코드 3건을 마무리해, 실기기 확인에 들어갈 수 있는 상태로 만든다.

1. **API §7 최적안 코드 반영**: `quality` 신호 전달, 증거 구간 24장(채널별 12장, 1초 간격), 요청 크기 상한, 보관 연장은 종료된 회차에만 허용.
2. **점검 미통과 입장자 모음**: 회차 상세 화면에 탭 하나를 추가한다. 응시자, 실패 항목, 입장 시각, 안내 메시지 보냄 여부를 보여 주고, 클릭하면 해당 응시자 감독 화면으로 이동한다. 서버는 저장된 `envCheck` 를 조회하는 API 만 추가한다.
3. **화면 공유 이벤트 서버 저장**: 공유 중단, 대상 변경, 재시작의 종류와 시각을 기존 감독 이벤트 목록에 함께 저장·표시한다. 이미지는 저장하지 않는다.

- 대상: 감독관·매니저(2, 3번 화면), 응시자 PC·휴대폰(1번 신호·업로드)
- 완료 기준: 각 항목이 자동 테스트를 통과하고 기존 테스트가 깨지지 않는다. 문서(API §7, 기록)에 반영한다. 실제 카메라·휴대폰 확인은 이번에 하지 않고 체크리스트에 남긴다.

## 제약

- 브랜치: **백엔드는 PR 없이 develop 에 바로 merge**(이번 작업에 한해 사용자가 지시, 평소 전략은 develop PR). 프론트는 개인 브랜치에서 테스트 후 main 에 merge. 문서는 main 에 바로 반영.
- DB 변경은 필요할 때만 한다.

## 하지 않을 것 (Out of scope)

- 운영용 휴대폰 릴레이·감독관 영상 시그널링 (별도 작업)
- 화면 공유 이벤트의 이미지 저장
- 콘솔에서 이벤트 앞 3장·뒤 3장만 먼저 보여 주는 변경 (논의 후 취소)
- 회차를 가로질러 모아 보는 별도 화면
- 실기기 확인, 오탐률·데이터 절감률 측정
