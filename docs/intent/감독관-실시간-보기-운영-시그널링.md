# 의도: 감독관 실시간 보기를 운영 서버(Spring)에 만들기

> 상태: 사용자가 2026-11-24 확정 (interview-me).
> 관련 문서: [API §6-11 감독관 실시간 영상 시그널링](../../API/실전시험_감독_API.md), [API §2 휴대폰 릴레이](../../API/실전시험_감독_API.md), [남은-코드-3건-마무리.md](남은-코드-3건-마무리.md)

## 목표 (Why)

감독관이 응시자 한 명을 골라 **웹캠과 화면 공유 영상을 실시간으로 보는 기능**을 **실제 서비스 서버(Spring)**에 만든다. 지금은 개발용 Vite 릴레이(`frontend/server/proctorRelay.ts`)에서만 되고, 운영 서버에는 이 기능(`watch`, `view-rtc` 시그널링)이 없다.

- 방식: 서버는 둘을 이어 주는 짧은 쪽지(시그널링)만 전달한다. 영상은 응시자 PC에서 감독관 브라우저로 직접 가고 서버를 지나지 않는다 (WebRTC).
- 대상: 감독관·매니저(보는 쪽), 응시자 PC(보내는 쪽).
- 완료 기준
  - 감독관이 응시자를 누르면 몇 초 안에 웹캠·화면 공유 영상이 나온다.
  - 연결이 안 되면 "영상 연결 안 됨"이 표시된다.
  - 자동 테스트와 개발 PC 두 대로 확인한다.

## 제약

- 서버는 **한 대** 기준이다. 연결 정보는 서버 메모리에 둔다 (지금 휴대폰 릴레이와 같다).
- **TURN 없이** 간다. 공개 STUN만 쓰고, 직접 연결이 안 되면 "영상 연결 안 됨"으로 표시한다.
- 감독관은 응시자를 **한 명씩 골라서** 본다.
- 브랜치: 백엔드는 `develop`에 바로 병합, 프론트는 개인 브랜치에서 테스트 후 `main`에 병합, 문서는 `main`에 바로 반영.

## 하지 않을 것 (Out of scope)

- 휴대폰 사진 전달(`/ws/proctor` 프레임 중계)의 상한 실측과 개선
- 서버를 여러 대로 늘리는 대응 (Redis 등 공용 전달 통로)
- TURN 서버 준비
- 응시자 여러 명을 한 화면에 모아 보기
- 실제 배포 서버에서 여러 네트워크로 시험하기
- 영상 녹화·저장
