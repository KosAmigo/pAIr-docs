## 현재 정책 (2026-11-24)

| 항목 | 상태 |
|---|---|
| 감독관 실시간 영상 (웹캠·PC 화면·휴대폰 3채널) | **사용 안 함.** 영상은 어디로도 실시간 전송하지 않는다 |
| 휴대폰 보조 캠 (JPEG 프레임 중계 포함) | **사용 안 함** |
| PC 화면 공유 | **사용 안 함** |
| 응시 시작 필수 연결 | **웹캠만** (끊기면 15초 유예 뒤 응시 화면 차단) |
| 부정행위 이벤트(웹캠) | 이벤트 발생 **앞뒤 웹캠 사진**만 서버에 올려 감독관이 확인·확정/기각한다 |
| 브라우저 이벤트 (탭 전환, 창·마우스 이탈, 전체 화면 해제, 붙여넣기) | 응시자에게 경고를 보여 주고, 감독관 콘솔에는 **발생 시각 등 이력만** 기록한다 (확정/기각 없음) |

> 프론트 스위치 `PHONE_CAM_ENABLED`, `SCREEN_SHARE_ENABLED`, `LIVE_VIEW_ENABLED` 와 백엔드 `PAIR_LIVE_VIEW_ENABLED` 는 **전부 꺼진 상태가 정책**이다. 코드는 지우지 않고 스위치로만 끈다. 2026-11-24 문서 정리 시점의 코드(`frontend/src/proctor/features.ts`)는 휴대폰 캠·화면 공유가 아직 `true` 이므로 코드를 이 정책에 맞추는 작업이 남아 있다.

## 목표 (Why)

- 응시자 PC 브라우저가 웹캠을 분석하고, 서버는 분석하지 않는다. 한 회차 **300명 이상** 동시 응시를 목표로 하므로 서버가 영상을 상시 받거나 분석하지 않는다.
- 다른 네트워크 시험에서 응시자가 핫스팟일 때 실시간 영상 연결(ICE)이 실패했다(STUN만 사용, TURN 없음). 휴대폰 보조 캠도 연결 끊김과 PC 부하 문제로 쓸 수 없었다. 그래서 **실시간 영상 없이 이벤트 기록과 사진 증거 중심**으로 감독을 단순하게 정리했다.
- 감독관이 영상을 안 보고 있어도 이벤트는 감지되고 기록되어야 한다. 모델은 선별만 하고 판단은 사람이 한다.
- 대상: 응시자(PC 웹캠), 감독관·매니저·관리자(콘솔).

## 확정한 내용

### 1. 감독 구조

- 웹캠 분석(얼굴 없음, 여러 얼굴, 고개 돌림·숙임, 시선 이탈, 자리 이동, 몸 돌림)은 응시자 PC 브라우저의 Worker 에서 한다. Worker 가 안 되면 메인 스레드로 폴백한다.
- 서버로는 **이벤트와 이벤트 앞뒤 웹캠 사진**만 간다. 연속 영상 전송·녹화·저장은 없다.
- 브라우저 이벤트는 모델 없이 바로 기록한다.
- 분석을 응시자가 끄거나 막을 수 있는 한계는 브라우저 이벤트의 서버 기록과 사람이 사진을 보는 검토로 줄이되 완전한 방어는 아니다.

### 2. 이벤트 앞뒤 증거 구간 · 검토 · 보관 연장

- 웹캠 이벤트가 나면 **앞 8초·뒤 4초**의 웹캠 사진(1초 간격, 최대 12장)을 PC 로컬 링 버퍼에서 올려 파일 저장소에 둔다. DB 에는 키와 이벤트 정보만 둔다. 요청 본문 2MB·사진 한 장 100KB 상한.
- 감독관·매니저가 **완료된 회차에서도** 타임라인으로 구간을 보고 확정/기각한다 (카메라 이벤트만. 브라우저 이벤트는 이력 보기만).
- 사진은 회차 종료 7일 뒤 자동 삭제한다. 삭제 2일 전부터 **회차 단위**로 7일씩 최대 2번(총 21일) 연장하고, 누가 언제 연장했는지 이력을 남긴다. 연장은 종료된 회차에만 허용한다. 알림은 콘솔 표시로만 한다.
- 카메라 이벤트 세부 내용은 좌표 숫자 대신 문장("시선이 오른쪽으로 31% 치우침 (기준 45% 넘으면 경고)")으로 보여 주고 원본 숫자는 숨긴다.
- 마우스 이탈은 좌우로 나간 것만 센다 (위·아래는 전체 화면 ESC 버튼·공유 안내 막대 때문에 제외).

### 3. 환경 점검 · 안내 메시지

- 점검에서 `fail`/`warn` 인 항목은 콘솔의 **"점검 미통과" 탭**에서만 본다 (응시자 열기 화면에서는 뺀다). 응시자, 실패 항목, 입장 시각, 안내 메시지 보냄 여부를 보여 주고 클릭하면 그 응시자 감독 화면으로 간다.
- 감독관·매니저·관리자는 자유 입력 안내 메시지를 시험 전·중 모두 보낼 수 있다. 응시자 화면에는 시험을 막지 않는 배너로 뜨고, "확인"을 누르면 콘솔에 읽음이 표시된다.
- 점검 항목은 PC(브라우저·원격·모니터·카메라·소음·조명·얼굴 위치 등)이고 휴대폰 점검은 쓰지 않는다. 점검 실패여도 입장은 허용한다.

### 4. 연결 유예 · 링크 만료 복구

- 웹캠 연결이 끊기면 15초 유예 뒤 응시 화면을 막고, 서버는 10초마다 연결 신호(heartbeat)를 받아 5분(유예)을 넘게 끊긴 응시자의 링크를 만료시킨다.
- 만료된 링크는 매니저·감독관·관리자가 콘솔에서 복구한다 (자기 회사 회차만). 복구하면 `enter`·`start`·`heartbeat` 가 다시 통과하고 `lastSeenAt` 을 지금으로 맞춘다. 누가·언제 복구했는지 `LINK_EXPIRED` 와 별개의 감독 이벤트로 남긴다. 종료 시각은 연장하지 않고, 이미 제출했거나 회차가 끝난 응시자는 복구하지 못한다. 횟수 제한은 없다.

### 5. 오탐·사진 유실·늦은 시작

- 같은 규칙이 계속 이어지면 이벤트 간격을 점점 늘린다 (6초 → 최대 60초, 정상으로 돌아오면 원래 간격). 응시자 화면에 "PC 기준 자세 다시 잡기" 버튼을 둔다.
- 서버 사진 상한(300장)에 막히거나 보관 기간으로 삭제됐거나 업로드가 실패한 경우 이벤트마다 "사진 없음" 사유를 구분해 보여 준다.
- 개발(코딩) 과제 회차용 기준값(`head_down` 지속 시간·각도)을 따로 두되, 숫자는 `FalsePositiveLab` 측정 결과로 정하고 조정 전후 오탐률을 남긴다.
- 입장 화면에 "늦게 시작하면 그만큼 시험 시간이 줄어든다"는 안내를 보여 준다. 종료 시각은 모두 같다.

## 제약

- 서버는 **한 대** 기준이고 연결 정보는 서버 메모리에 둔다.
- 서버로는 이벤트와 사진만 보낸다 (영상 전송 없음).
- 브랜치: 백엔드는 `develop` 에 PR, 프론트는 개인 브랜치에서 테스트 후 `main` 에 병합, 문서는 `main` 에 바로 반영.

## 하지 않을 것 (Out of scope)

- 감독관 실시간 영상 보기(웹캠·화면·휴대폰), 응시자 여러 명 한 화면 보기, TURN 서버
- 휴대폰 보조 캠, 휴대폰 JPEG 프레임 중계, PC 화면 공유 (코드는 남겨 두고 스위치로만 끈다)
- 연속 영상 녹화·저장, 서버의 상시 영상 분석·서버 추론(RunPod 등)
- 신분증 확인, 화면 속 내용 분석, 방 360도 스캔
- 시험 시간 연장, 5분 유예 기준값 변경, 개인별 시간 보정, 서버 사진 상한 300장 변경
- 응시자 답장·채팅, 정해진 문구 목록, 점검 기준을 콘솔에서 바꾸는 기능
- 서버를 여러 대로 늘리는 대응, 메일·푸시 등 새 알림 시스템, 무제한 보관 연장
- 실기기 확인·오탐률·데이터 절감률 측정은 별도 작업(체크리스트)

## 폐기한 방향 (이력)

- 2026-11-21 **웹캠 + 휴대폰 + PC 화면 공유 3채널 연결 필수**: 휴대폰 연결이 시험 내내 유지되지 않아 같은 날 휴대폰·화면 공유를 스위치로 껐다. 11-23 에 JPEG 프레임 중계 방식으로 휴대폰 캠과 화면 공유를 다시 켰으나, 11-24 에 **전부 사용 안 함**으로 최종 정리했다.
- 2026-11-24 **감독관 실시간 영상 보기(WebRTC P2P, 운영 시그널링 구현)**: 핫스팟 응시자에서 ICE 실패. 코드·서버 시그널링은 남기고 꺼 두었다.
- **정현의 서버 GPU 추론 제안**: 분석은 응시자 PC 브라우저에서 한다는 방향이 확정되어 쓰지 않는다.
