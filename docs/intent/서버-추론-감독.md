# 서버 추론 감독 (웹캠·휴대폰 분석을 RunPod GPU 서버로)

> 2026-11-25 확정, **같은 날 보관·저장 정책을 개정**(휴대폰 사진 상시 저장, 보관 3일). **2026-11-26: 모델 선택 확정과 남은 가정(연장 규칙, 휴대폰 사진 사후 열람, 태블릿 등의 출처)을 사용자가 확정했다.** 이전 방침("서버는 분석하지 않고 PC 브라우저가 분석한다", [실전시험-감독.md](실전시험-감독.md))을 이 문서가 **대체**한다.
> 작업 브랜치: 백엔드 `feat/server-vision`(develop 기준), 프론트 `feat/server-vision`(main 기준). 추론 서버 코드는 새 저장소.

## 목표 (Why)

- 웹캠과 휴대폰 분석을 모두 **RunPod GPU 추론 서버**에서 한다. 응시자 PC는 사진만 보낸다.
- 웹캠·휴대폰 사진은 응시 중 **각각 초당 1장씩 파일 서버에 상시 저장**하고, 이상 행동 이벤트가 나면 그 시각의 **앞 8초·뒤 4초 사진**을 상시 저장분에서 꺼내 감독관·매니저가 사후에 확정/기각한다. 판단은 사람이 한다. (2026-11-25 개정: 처음에는 이벤트일 때만 저장 → 웹캠 상시 저장 → 휴대폰까지 상시 저장)
- 이유: 분석이 응시자 PC에 있으면 결과를 조작할 수 있고, 느린 PC에 부담이 되며, 휴대폰 분석을 PC에서 돌리는 데 한계가 있다(아이폰 메인 스레드 점유, 11-21 기록).

## 확정 사항

| 항목 | 내용 |
|---|---|
| 대상 | 응시자 약 30명(동시), 사후 검토하는 감독관·매니저 |
| 핵심 규칙 | 손이 키보드·마우스 영역 밖에 있는 상태를 탐지. **두 손 모두 밖: 7초 이상**이면 이벤트, **한 손만 밖(다른 손은 키보드나 마우스 위): 10초 이상**이면 이벤트 |
| 모델 (2026-11-26 확정) | **D-FINE-s + OWLv2 + MediaPipe Hands로 확정, 그림자 모드 후 재확정.** 키보드·마우스·노트는 D-FINE-s(휴대폰 프레임 매번, 노트는 COCO `book`), 태블릿·스마트워치·(다른)휴대폰은 OWLv2(몇 초마다), 손은 MediaPipe Hands. 제외: RT-DETR-r18, Grounding DINO, YOLO 계열(AGPL). 직접 학습은 그림자 모드 결과가 부족할 때의 선택지로만 남긴다. 근거: RunPod RTX 4000 Ada 측정과 사진 8장 비교(설계 §8-5) |
| 보조 탐지 | 태블릿·메모·스마트워치. **이 물체들의 이벤트는 휴대폰 화면 기준(`source=PHONE_CAM`)으로 기록한다(2026-11-26 사용자 결정).** 정확도 목표 수치는 아직 없고, 그림자 모드 데이터로 먼저 측정한 뒤 정한다 |
| 휴대폰 위치 | 책상 옆 거치대에 세워 키보드·마우스·두 손이 모두 보이게 한다 |
| **휴대폰 영상·사진 표시** | **라이브 영상은 어디에도 보여 주지 않는다(응시자 미리보기 포함, 감독관 실시간 보기 없음).** 입장 점검은 영상 대신 "키보드 인식됨·마우스 인식됨·두 손 인식됨" 같은 서버 판정 결과로 확인한다. **사후 사진 검토는 허용**: 이벤트 구간(앞 8초·뒤 4초)과 감독 중단 구간에 한해 감독관이 휴대폰 사진을 볼 수 있다 **(2026-11-26 사용자 확정, 설계 D-23)** |
| 서버 장애 | PC 분석 폴백 없음. 서버가 죽어도 시험은 계속 진행하고 그 구간은 "감독 중단"으로 기록한다. 서버는 최대한 안 죽게 운영한다(최신 프레임만 처리, 상태 확인·자동 재시작). 추론 서버는 **1대 고정**, 부하가 많으면 2대로 늘리고 Grafana로 모니터링한다. 서버가 안 뜬 상태에서도 입장은 허용하고 감독 중단으로 기록한다 |
| 사진 저장·보관 (2026-11-25 확정) | **웹캠·휴대폰 사진 모두 초당 1장 상시 저장**(백엔드가 10초 묶음으로 파일 서버 S3에 저장, 추론 서버와 독립). 상시 저장분은 **시험 종료 후 3일** 보관. 이벤트 시각으로 앞 8초·뒤 4초를 꺼내 따로 남기는 **이벤트 구간도 3일 보관, 3일 단위로 연장 가능**. **이벤트 구간 연장은 최대 2번, 삭제 1일 전부터 가능(2026-11-26 사용자 확정, 기존 규칙 유지).** 상시 저장분 자체의 연장 여부는 정하지 않았다. **서버 추론이 꺼진 회차는 기존 규칙(7일, 7일씩 최대 2번)이 그대로** 적용된다. 용량 추정: 30명·2시간 약 6.5~8.6GB(실측 전) |
| 손 규칙 세부 | 끊김 3초까지는 같은 상태로 이어서 센다. 입장 보정에서 키보드·마우스에 **두 손이 모두 인식**되어야 통과한다(한 손 응시자 입장 경로는 미정) |
| 운영 | 추론 서버는 **시험이 있는 시간에만** 켠다. 시험 30분 전에 미리 켜 두는 운영이 필요하다(GPU 확보 실패 위험) |
| 배포·롤백 | 스위치를 끈 채로 배포. 로컬 테스트 → 메인 병합·배포 테스트 → 안 되면 롤백(스위치를 끄는 것으로 되돌린다) |
| 동의 문구 | v3로 올린다. 웹캠·휴대폰 사진이 해외 서버(RunPod)로 보내져 AI가 분석하고, 두 사진 모두 초당 1장 상시 저장되어 시험 종료 3일 뒤 삭제되며 이벤트 구간은 3일 단위로 연장될 수 있다는 내용(초안은 설계 §13). **국외 이전은 동의 문구에 넣어 고지하고 진행한다(사용자 결정).** 법적 충분성은 확인하지 못했으므로 실응시자 파일럿 전 법무·개인정보 담당 확인 1회 권장 |

## 하지 않을 것 (Out of scope)

- 감독관의 실시간 영상 보기, 영상 녹화, 화면 공유·화면 녹화 (웹캠·휴대폰 사진을 초당 1장 저장하는 것은 영상 녹화가 아니라 하는 일이다)
- 휴대폰 **라이브 영상** 표시(응시자 미리보기 포함). 사후 사진 검토는 위 확정대로 허용하며 이 항목에 해당하지 않는다
- 얼굴로 신원 식별
- 자동으로 부정행위 확정
- 키보드·마우스 외의 손 위치·자세 규칙
- PC 분석으로 되돌아가는 폴백

## 아직 정해지지 않은 것

- 일정
- 태블릿·메모·스마트워치의 정확도 목표 수치
- 입장 점검에서 휴대폰 위치를 확인하는 구체적인 방식(영상 없이)
- RunPod 구성(pod 종류, GPU 사양). 추론 서버 저장소는 `pAIr-vision`으로 만들어졌다
- 웹캠·휴대폰 사진 크기·전송 간격, 서버 동시 처리 용량 산정(실측, 동시 처리량은 아직 미측정)
- 웹캠(얼굴·포즈) 분석의 서버 CPU 부하(미측정)
- 상시 저장분 자체의 연장 여부
