# 2026-11-19 감독을 실전 시험에 합치고 회차 백엔드 구축

> 커밋: pAIr-back `de9bdb1`, `318bc72`, `8320eff`, `8acb587`, `ca761b1`, `7a91751`, `9fac8fc`, `f8b653f` / pAIr-front `abb37e8`, `e2b05a8`, `81ef0ab`, `03636eb`

## 한 일

- **카메라 감독을 실전 시험 흐름에 합쳤다.** 따로 있던 `cam-proctor` 를 `frontend/src/proctor` 로 옮기고, 입장 링크(`?invite=`)로 실제 데이터를 받아 실제 환경 점검, 서버 시각 기준 자동 시작까지 이었다. 감독은 실전 맥락일 때만 켜지고 **자가진단은 감독을 끈다.**
- **회차 백엔드**: 마이그레이션 V1·V2·V3, 사진 S3 저장소, 대상자 CSV 업로드(미리 보기·행별 사유·원본 보관), 시작 하루 전 알림 메일, 회차 취소(`canceled_at`), 담당자 판정(OK/SUSPECT), 과제별 제출 API, 콘솔 인증 경계(회사 분리).
- **오탐률 측정 도구** `/proctor/lab`: 조명·각도·안경 조건을 고르고 N분 정상 응시하면 규칙별 분당 오탐 수, 기준값 버전별 비교, CSV.
- 외부 붙여넣기(`PASTE`)와 브라우저 이탈 이벤트를 회차 감독 기록으로 전송(글 내용은 보내지 않음).
- 테스트: 감독 규칙·점검 38개, 연결부 13개, 회차 전체 흐름 통합 테스트(H2).

## 기술 선택

| 결정 | 선택 | 이유 |
|---|---|---|
| 초대 토큰 | `SecureRandom` 32바이트, DB 에는 SHA-256 해시만, 재발송하면 새 토큰 | DB 가 새도 링크를 만들 수 없고, 잘못 보낸 링크를 무효로 만들 수 있다 |
| 대상자 등록 | 엑셀 → 사이트 양식 CSV, 올리기 전 미리 보기, 원본 보관 | 엑셀마다 형식이 달라 읽기 오류가 잦고, 틀린 줄을 올리기 전에 보여 줘야 한다 |
| 회차 삭제 | 지우지 않고 `canceled_at` 기록 | 취소한 회차도 감독·메일 기록을 남겨야 한다 |
| 사진 보관 | 회차 종료 30일 뒤 삭제 (11-23 에 7일로 변경 결정) | 개인정보 보관 기간 제한. 담당자가 판정할 시간 확보 |
| 코드 실행 경계 | `CurrentUser` 인터페이스(개발은 `X-Pair-*` 헤더, Spring Security 가 붙으면 구현만 교체) | 팀원 1 의 로그인이 아직 없어도 회사 분리(401·403·404)를 먼저 만들고 테스트할 수 있다 |

## 문제와 해결

### 1. 서버가 아예 안 켜짐

- **증상**: 서버가 시작되지 않았다.
- **원인**: 사진 검증 클래스의 빈(Bean) 생성이 실패했다. 커밋에는 "생성자 지정"으로만 적혀 있어 정확한 실패 메시지는 기록돼 있지 않다.
- **해결**: 사용할 생성자를 지정했다. (`de9bdb1`)
- **확인**: 회차 전체 흐름 통합 테스트가 이제 서버 컨텍스트를 실제로 띄워 확인한다.

### 2. 마이그레이션 누락

- **증상**: 다른 환경에서 실전 시험 테이블이 없었다.
- **원인**: 이전 커밋에 Flyway `V1__exam_sessions.sql` 이 빠져 있었다.
- **해결**: 추가. 적용된 V1 은 체크섬 때문에 이후 고치지 않기로 했다. (`de9bdb1`, `9fac8fc`)
- **남은 일**: V1~V14 를 실제 PostgreSQL 에 순서대로 적용해 보는 확인은 아직 H2 테스트까지만 했다.

### 3. 초대 메일 결과 기록이 응시 시작 기록을 덮어씀 (경쟁 상태)

- **증상**: 메일 발송 결과를 기록하는 작업이 응시 시작 기록을 덮어썼다.
- **원인**: 비동기로 보낸 메일의 결과 저장과 응시 시작이 같은 기록을 동시에 갱신하는 경쟁 상태. 커밋에는 "덮어쓰던 경쟁 상태 수정"으로만 적혀 있다.
- **해결**: 메일 결과 기록이 응시 시작 기록을 덮지 않도록 수정. (`8320eff`)

### 4. 대상자 한 줄이 틀리면 전체가 거절됨

- **증상**: 잘못된 행이 하나만 있어도 대상자 추가가 통째로 거절됐다.
- **해결**: 행별 사유를 돌려주고 올바른 줄은 등록한다. (`de9bdb1`)

### 5. 지원하지 않는 메서드가 500 으로 응답

- **해결**: 지원하지 않는 메서드는 405, 맞지 않는 본문 형식은 415 로 응답한다. (`8acb587`, PR #2)

### 6. 이벤트 전송 실패 처리

- 브라우저 아웃박스가 **네트워크 오류·5xx 만 다시 보내고 4xx 는 버린다.** 잘못된 요청을 계속 두드려 서버를 괴롭히지 않기 위해서다. (`318bc72`)

### 7. 저장소 구조를 두 번 번복

- IntelliJ 로 저장소를 열면 Gradle 프로젝트로 인식되지 않아 Gradle 루트를 최상위로 올렸다가(`9fac8fc`), 프론트와 같은 구조(`backend/` 안에 코드·빌드 설정)로 다시 돌렸다(`f8b653f`, `7a91751`).
- 이때 `pilot-data` 폴더가 저장소 밖(`C:/dev`)에 생기던 문제도 같이 고쳤다. 원인은 bootRun 작업 폴더가 저장소 최상위가 아니었기 때문이다.

### 8. 동의 문구와 실제 설계가 다름

- 입장 화면 동의 문구를 실제 설계(영상 미전송, 사진 1장, 7일 뒤 삭제)에 맞췄다. 그 뒤 서버 보관이 30일로 정해져 어긋났으나, 11-23 에 **7일로 확정**했다(문서 반영 완료, 서버 설정값 변경은 남음).
