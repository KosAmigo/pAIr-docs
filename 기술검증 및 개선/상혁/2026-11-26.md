## 문제와 해결

### 1. 시선(`GAZE_AWAY`)이 계약 해상도에서 믿을 수 없었다

- **증상**: 같은 사진의 시선 값이 400px·q55 에서 640px 의 절반 이하(±0.3 대 ±0.7)로 줄고, 기준값 0.45 를 거의 못 넘는다. 정면에서도 `gaze_y` 가 ±0.15~0.3 흔들렸다(본인 사진 1명).
- **결정**: **서버 추론은 `GAZE_AWAY` 를 만들지 않는다**(확정). 서버 모드에서는 PC 분석과 달리 시선 이벤트가 없다.

### 2. 손 3개 이상(`MANY_HANDS`)

- **결정**: 이벤트 유형으로 추가하지 않는다(확정). 지표·로그에만 남긴다.

### 3. 설계 문서와 구현의 값이 갈리는 곳

- 휴대폰 이벤트 `TABLET`·`NOTE`·`SMARTWATCH` 는 `PHONE_CAM` 만으로 정했다(웹캠에서는 만들지 않음). 구현 세션이 임시로 정한 지속·쿨다운·기준값은 설계 §7-3 에 "가정" 표로 옮겼다.

## 확인

- 추론 서버: 책상 사진 8장 + 본인 웹캠 사진 10장, 이 PC CPU 에서 손·물체·웹캠 이벤트가 **서명된 콜백으로 도착**하는 것까지 확인. 실제로 발생한 이벤트: `HANDS_OUT` `HAND_OUT_ONE` `TABLET` `NOTE` `SMARTWATCH` `NO_FACE` `HEAD_TURN`. 60스트림 재생에서 `maxSessions=40` 일 때 20개가 `OVER_CAPACITY` 로 거절되는 것도 확인.
- 백엔드·프론트: 단위·통합 테스트 파일이 커밋에 포함돼 있다(`VisionSignatureServiceTest`, `StreamPackCodecServiceTest`, `StreamRecorderServiceTest`, `VisionHealthServiceTest`, `SnapshotRetentionVisionTest`, `VisionInternalApiIntegrationTest`, `tests/proctor/serverVision.test.ts`). **이 기록을 쓰며 테스트를 다시 돌려 통과를 확인하지는 않았다.**
- **못 한 것**: `HEAD_DOWN`(숙이면 얼굴을 놓쳐 `NO_FACE` 로 셈), `MULTI_FACE`·`TORSO_*` 는 합성 값 시험만, GPU 에서의 OWLv2 미검증(CPU 에서 프레임당 약 3초라 로컬은 OWLv2 주기 30초), 실제 카메라·휴대폰·RunPod·여러 응시자 동시 부하는 확인 못 했다. 사진이 적어 정확도는 확정이 아니다.
