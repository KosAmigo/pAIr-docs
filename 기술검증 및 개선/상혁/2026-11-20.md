## 문제와 해결

### 1. 시험 시간이 끝나도 채점이 시작되지 않음

- **증상**: 후속 질문 단계에서 시간이 끝난 응시가 "제출 완료"로 보이는데 채점 큐에 올라가지 않았다.
- **원인**: 자동 제출이 "풀이 중(SOLVING)" 응시만 제출했다. 후속 질문(FOLLOWUP) 단계 응시는 건드리지 않았고, 채점은 그 단계를 끝내야 시작된다.
- **해결**: 종료 시각에 시작한 응시자 전원의 응시를 마무리한다(`finishAll`). 풀이 중이면 제출하고, 후속 질문 단계면 **빈 답으로 마무리해** 채점으로 넘긴다. 이미 채점 단계인 응시는 건드리지 않아 두 번 돌아도 안전하고, 한 응시가 깨져도 나머지는 계속한다.
- **확인**: 단위 테스트 `AttemptSubmitterFinishTest` 와 통합 테스트. (`7e3d7ef`)

### 2. 채점으로 못 넘긴 응시가 있어도 회차가 닫힘

- **증상**: 마무리에 실패한 응시가 있어도 회차를 닫아서 그 응시는 영영 채점되지 않았다.
- **해결**: 실패하면 회차를 **닫지 않고** 간격을 늘려(2·4·8초 … 최대 30초) 다시 시도한다. 5번 실패하면 같은 응시를 계속 두드리지 않도록 포기하고 닫으며 오류 로그를 남긴다. 재시도 상태는 서버 메모리에만 두므로 서버를 다시 켜면 처음부터 센다.
- **확인**: 통합 테스트 2개(재시도 뒤 포기, 재시도에서 성공). (`80b03fc`)

### 3. 포기한 응시를 사람이 되살릴 방법이 없음

- **해결**: 종료된 회차에서 채점으로 못 간 응시를 다시 넘기는 복구 API `POST /api/console/sessions/{id}/rescue` 와 콘솔 결과 탭의 "멈춘 응시 다시 넘기기" 버튼. 종료된 회차에서만 쓸 수 있고, 권한이 없으면 403, 다른 회사 회차면 404. (`41ff028`, `c9baf53`)

### 4. 시험 중 연결이 끊기면 어떻게 할지 정해져 있지 않음

- **해결**: 시험 화면이 10초마다 `heartbeat` 를 보낸다. 90초 넘게 끊겼다 돌아오면 `CONNECTION_LOST` 를 남기고, 마지막 신호 뒤 5분 안에 돌아오지 못하면 링크를 만료(`LINK_EXPIRED`)시킨다. 돌아오지 않는 경우는 30초 주기 점검이 기록한다. 자동 탈락은 없고 담당자가 보는 기록이다. (`69b1dc4`, V11)
- 이 두 기록은 응시자 화면이 보내는 이벤트로는 받지 않고 서버만 남긴다(응시자가 조작하지 못하게).
- 프론트의 15초 유예는 [11-21](2026-11-21.md) 에 붙였다.

### 5. 감독 기록이 두 군데에 저장됨

- **증상**: 11-17 의 브라우저 이벤트 감독이 별도 API·저장소를 써서, 회차 감독 이벤트(카메라)와 기록이 나뉘어 있었다.
- **해결**: 별도 API·저장소·테스트를 지우고(`e176afe`, 387줄 삭제) 프론트의 별도 전송 코드도 걷어(`a885297`) 회차 감독 이벤트 DB 로 통합했다.

### 6. 정밀 분석(OWL-ViT) 제거

- 점검 사진을 글로 지정한 물체 찾기 모델(OWL-ViT)로 다시 보던 기능과 의존성을 제거했다. 같은 커밋에서 귀 확인 판정을 개선했다(35도 이상 돌려 0.3초 유지, 옆모습에서 얼굴 모델이 얼굴을 놓쳐도 0.7초 안에 돌리고 있었다면 인정). (`c8c04bf`)
- **제거 사유 (작성자 확인)**: 탐지 수치(기준값)를 조정해 봐도 너무 빡세면 정상 물건까지 "검토 필요"로 잡히고, 풀면 정작 이어폰·메모지를 놓치는 식으로 **적정 수준을 찾을 수 없었다.** 글로 지정해 찾는 모델은 물체마다 신뢰도 분포가 달라 하나의 기준값으로 맞추기 어려웠던 것으로 보인다(이 해석은 추정). 조정 전후 수치는 기록하지 않았다.
- **대신 택한 방식**: 자동 판정을 포기하고 사진과 일반 물체 목록(EfficientDet-Lite0)만 감독관에게 넘겨 사람이 판단한다. 같은 원칙이 "책상 위 감지는 경고만 하고 통과"에도 쓰였다.
- **교훈**: 오탐·미탐 사이에서 기준값이 균형을 못 잡는 감지는 모델을 키우기보다 사람 판단으로 넘기는 편이 낫다. 이후 감지 항목의 기준값은 `/proctor/lab` 로 조정 전후를 숫자로 남긴다.
