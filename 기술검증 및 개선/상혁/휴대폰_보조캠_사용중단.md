# 휴대폰 보조 캠 사용 중단 정리

> 2026-11-21 16:29 pAIr-front `3f2238c` (정현 커밋) 으로 휴대폰 보조 캠과 PC 화면 공유를 꺼 두었다. 이 날 중단 직후에는 웹캠만 필수였다. **11-23 에 화면 공유는 다시 켜서, 현재는 웹캠 + PC 화면 공유 필수이고 꺼져 있는 것은 휴대폰 보조 캠뿐이다.**
> 근거 수준: **기록** = 코드·문서에 적혀 있음 / **로그** = 재현 로그 / **추정** = 기록이 없어 짐작. 중단 결정 때 남은 설명은 커밋 메시지에 없어, 아래 "왜 멈췄나"는 코드 주석·문서에서 모은 것이다.

| 지금 응시 조건 | 웹캠과 PC 화면 공유가 연결되면 환경 점검 통과 → 대기실 입장 → 시험 시작 (휴대폰은 불필요) |

| 누가 | 중단 커밋은 정현(`ahnjh97`), 휴대폰 캠 구현은 상혁 |

## 3. 왜 멈췄나

| 이유 | 내용 | 수준 |
|---|---|---|
| 실제 서비스에서 동작하지 않음 | `features.ts` 주석: "휴대폰 연결 코드(릴레이·QR·스캔)는 구현만 해 두었고 실제 서비스에서는 동작하지 않으므로 화면에 보여 주지 않는다" | 기록 |
| 다른 망(LTE 등)에서 영상이 안 나옴 | 터널은 영상을 못 넘기고, 직접 연결이 막힌 망에는 **TURN 서버**가 필요한데 아직 없음. 담당 명세: "LTE 등에서 TURN 서버가 필요한 한계가 있어 보류" | 기록 |
| 운영 릴레이가 없음 | 휴대폰 짝짓기·신호 중계·감독관 영상 시그널링이 개발용 Vite 릴레이에만 있고, 운영(Spring WebSocket) 구현이 없음 | 기록 |
| 연결 안정성을 실기기로 확인 못 함 | 분석을 PC 로 옮기고 기준을 15초로 늘렸지만, 아이폰에서 시험 내내 유지되는지는 사람이 확인하지 못함(체크리스트 A3·A4) | 기록 |
| 시험 직전 단계 부담 | 응시자가 휴대폰을 세우고 QR 을 찍고 점검하는 단계가 늘어, 입장 단계 실패 지점이 늘어남 | 추정 |

한 가지 이유가 아니라 "운영 환경에서 쓰려면 아직 갖춰야 할 것(TURN, 운영 릴레이, 실기기 검증)이 남아 있어서 보류"에 가깝다. 정확한 결정 사유는 정현에게 확인이 필요하다.

## 4. 중단으로 바뀐 것

| 영역 | 전 | 후 |
|---|---|---|
| 응시 조건 | 웹캠 + 휴대폰 + PC 화면 공유 (세 채널, 15초 유예) | 웹캠만 (11-23 부터 웹캠 + PC 화면 공유) |
| 책상 위 스캔 | 휴대폰이 책상을 비추고 PC 가 물체 감지, 경고 후 통과 | **없음.** 책상 위 사진이 올라오지 않음 |
| 감지 항목 | 손 화면 이탈, 휴대폰·책·다른 화면, 휴대폰 연결 끊김 | 웹캠 감독(얼굴 없음·여러 얼굴·고개·시선·자리 이동)과 브라우저 이벤트만 |
| 감독관 영상 보기 | 휴대폰·웹캠·화면 3채널 | 웹캠 채널 중심 (개발 릴레이만) |
| 서버 | `env_scan_photos`, `PHONE_*`·`SCREEN_*` 이벤트 | 코드와 테이블은 유지, 프론트가 보내지 않음 |
| 개발 실행 | 터널로 켬 | `dev-all.mjs` 는 터널 없이 켜는 것이 기본, `--tunnel` 로만 켬 |

**잃은 것**: 책상 위 물건(휴대폰·책)과 손 움직임을 보는 감독. 웹캠은 얼굴·상체만 보므로 책상 위는 볼 수 없다.
**얻은 것**: 응시자 입장 단계가 단순해지고, 휴대폰 연결 끊김으로 응시가 막히는 일이 사라졌다.

## 5. 다시 켜려면

1. TURN 서버 준비 (무료 플랜: Metered 월 20GB 등, 또는 coturn 직접 설치) 후 `VITE_TURN_URL`·`VITE_TURN_USERNAME`·`VITE_TURN_CREDENTIAL` 설정
2. 운영용 릴레이를 Spring WebSocket 으로 구현 (휴대폰 짝, 감독관 시그널링·권한·열람 기록)
3. 실기기 체크리스트의 A(휴대폰 연결), B(휴대폰 분석), C(책상 스캔), D(세 채널), E(화면 공유) 통과 확인
4. 화면 공유는 서버가 `source=SCREEN` 이벤트를 받게 한 뒤 `SCREEN_EVENTS_ACCEPTED=true`
5. `features.ts` 의 `PHONE_CAM_ENABLED`·`SCREEN_SHARE_ENABLED` 를 `true` 로

## 6. 배운 점

- 분석 위치를 휴대폰에서 PC 로 옮기는 것으로 부하 문제는 풀었지만, **기능이 동작하려면 기술 외에 인프라(TURN, 운영 릴레이)와 실기기 검증이 필요**했다. 개발 환경(같은 와이파이, 개발 릴레이)에서만 되던 것을 운영 가능으로 착각하기 쉽다.
- 코드를 지우지 않고 스위치로 끈 덕분에 되살리는 비용이 작다. 기능 단위로 스위치를 두는 방식은 다음에도 쓴다.
