# 오탐 폭주·사진 유실 사유·기준값 조정, 늦은 시작 안내

## 목표 (Why)
- 실전 시험의 감독에서 자세가 한 번 바뀌면 같은 이벤트·사진이 6~10초마다 쌓여 수백 건이 되고, 서버 사진 상한(300장)과 브라우저 아웃박스 상한(100건)을 넘으면 뒤쪽 증거가 아무 표시 없이 사라진다. 감독관은 "사진 없음"의 사유를 알 수 없다.
- 개발(코딩) 시험에서는 키보드를 내려다보는 일이 흔해 `head_down`(5초) 같은 기준이 오탐을 많이 만든다.
- "전원 동시 시작"은 입장 허용 시각(`startsAt`)과 공통 종료 시각(`endsAt`)만 같다는 뜻인데, 늦게 시작하면 시간이 줄어든다는 사실이 응시자에게 안내되지 않는다.

## 확정한 내용

### 4번 (감독 오탐·증거 유실)
- 4-a 폭주 억제
  - 응시자 화면에 "PC 기준 자세 다시 잡기" 버튼을 추가한다 (지금은 휴대폰 기준만 있음).
  - 같은 규칙이 계속 이어지면 이벤트 간격을 점점 늘린다 (예: 6초에서 최대 60초). 정상으로 돌아오면 원래 간격으로 되돌린다.
- 4-b 사진 유실 사유 표시
  - 서버가 사진 상한에 막아 사진을 받지 않은 이벤트에는 그 사유를 기록한다.
  - 감독관 화면은 "사진 없음"을 상한 초과, 보관 기간 삭제, 업로드 실패로 구분해 보여 준다.
  - 브라우저 아웃박스가 오래된 건을 버릴 때는 이벤트는 남기고 사진만 버린다.
- 4-c 기준값 조정
  - 개발(코딩) 과제 회차용 기준값을 따로 둔다 (`head_down` 지속 시간, 각도 등).
  - 숫자는 `FalsePositiveLab`로 측정한 결과로 정하고 근거 없이 임의로 바꾸지 않는다. 조정 전후 오탐률을 비교할 수 있게 남긴다.

### 5번 (늦은 시작)
- 입장 화면에 "늦게 시작하면 그만큼 시험 시간이 줄어든다"는 안내 문구만 추가한다.

## 완료 기준
- 같은 자세 이탈이 이어져도 이벤트 수가 눈에 띄게 줄어든다.
- 사진 없는 이벤트마다 사유가 보인다.
- 5번은 입장 화면에 안내 문구가 보인다.

## 제약
- 서버로는 이벤트와 사진 1장만 보낸다 (영상 전송 없음).
- 5번은 종료 시각 공통과 자동 제출 방식을 그대로 둔다.

## 하지 않을 것 (Out of scope)
- 개인별 시간 보정, 시작 마감 규칙
- 서버 사진 상한 300장 자체 변경
- 감독 이벤트 판정 흐름 변경
- 1~3번 항목 (연결 기준 통일, 중복 접속 감지, 링크 복구는 별도 완료)
