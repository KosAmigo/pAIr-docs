# 기술검증 및 개선

pAIr 개발 중에 **왜 그 기술·모델을 골랐는지**, **어떤 큰 문제를 어떻게 풀었는지**를 팀원별·일자별로 남기는 폴더다.
`기획/기술검증_보고서_정현.md` 가 "후보를 돌려 비교한 결과표"라면, 이 폴더는 개발 날짜 순서대로 "그때 무슨 문제가 있었고 무엇을 바꿨는가"를 적은 기록이다.

## 구조

```
기술검증 및 개선/
├─ README.md            이 파일 (작성 규칙)
└─ <팀원 이름>/
   ├─ README.md         한눈에 보는 일정, 큰 문제 목록
   ├─ 선택_근거.md       기술·모델을 고른 이유 한곳에 모은 표
   └─ YYYY-MM-DD.md     그날 한 결정과 해결한 문제
```

| 팀원 | 폴더 | 담당 |
|---|---|---|
| 상혁 (팀원 4) | [상혁/](상혁/README.md) | 실전 시험 흐름: 회차·초대·입장·카메라 감독·자동 제출·결과 분석 |
| 문희 (팀원 3) | [문희/](문희/README.md) | 응시 흐름·복기 |
| 성진 (팀원 1) | [성진/](성진/README.md) | 인증·회사 분리·크레딧·채점 큐·배포·모니터링 |

## 작성 규칙

- 일자 파일은 **git 커밋 날짜**를 기준으로 쓴다. 커밋 해시를 같이 적어 코드에서 찾을 수 있게 한다.
- 문제는 `증상 → 원인 → 해결 → 확인` 순서로 쓴다. 원인을 모르면 "원인 미확정"이라고 적는다.
- 숫자에는 **근거 수준**을 붙인다: `측정`(직접 재 봄), `로그`(재현 로그로 확인), `테스트`(자동 테스트 통과), `논리`(장단점으로 판단), `추정`(기록이 없어 코드·문서로 짐작).
- 새 팀원은 같은 구조로 자기 이름 폴더를 만든다.
