## 측정 결과 (팀원 3: 응시 흐름)
제품 코드로 직접 쟀다(2026-11-21, 8코어 맥, 실제 PostgreSQL). 방법과 표는 [담당_기술명세_문희.md](기획/담당_기술명세_문희.md) 8절, 측정 테스트(`CheckpointRestoreBenchTest`, `JavaDiagnosticsBenchTest`, `SandboxConcurrencyBenchTest`)는 평소 빌드에서 쓰이지 않아 2026-11-24 에 삭제했다(커밋 `9a2f4ff`). 다시 잴 때는 `9a2f4ff^` 에서 파일을 되살려 `PAIR_BENCH=1` 로 돌린다.

| 항목 | 목표 | 결과 | 조건 |
|---|---|---|---|
| 체크포인트 복원 | 1초 이내 | 중앙값 2.5~5.4ms, 최대 9.7ms | 질문 1~40개, 파일 11개 6KB, 질문마다 1개 또는 11개 변경 (`CheckpointRestoreBenchTest`) |
| 롤백(새 응시 만들기) | - | 질문 40개에서 99~151ms | 위와 같음, 파일·앞 대화 복사 포함 |
| 편집기 진단·자동 완성 | 0.3초 이내 | 한 번 15~35ms(95% 67ms 이내), 동시 32명이 쉬지 않고 요청해도 응답 평균 0.2초·거절 0, 동시 4개 한도 처리량 약 110~150건/초, 힙 최대 약 270MB | 작업 파일 9개 5천 자 (`JavaDiagnosticsBenchTest`) |
| 코드 실행(Docker) 동시 | 상한을 정하는 근거 | 동시 1개 5.5초, 4개 7.2초, 8개 8.8초, 16개 28.2초(전부 성공) | 실행당 CPU 1·메모리 512MB·제한 30초, 상한 해제 (`SandboxConcurrencyBenchTest`) |
| 악성 코드 격리 | 모두 차단 | 6종 모두 차단 (무한 루프, 메모리 폭주, 인터넷, 스레드 폭주, 디스크 채우기(`/tmp` 64MB 한도), 읽기 전용 파일 시스템·일반 사용자)하고 실행 뒤 컨테이너가 남지 않음 | `SandboxIsolationTest` 7개 |

한계: 작은 파일, 같은 PC의 DB, 예열 후 값이다. 원격 DB·낮은 사양 서버에서는 달라지므로 서버 사양이 정해지면 다시 잰다. 샌드박스 서버 사양 계산은 [API/응시_흐름_API.md](API/응시_흐름_API.md) 9절을 본다.

## 측정 결과 (팀원 1: 동시 제출·채점)
동시 제출 100건 부하 테스트(2026-11-26). 방법·전체 표·한계는 [검증_결과.md](검증_결과.md) 5절, 다시 재는 법은 pAIr-back `loadtest/submit_load.py`.

| 항목 | 결과 | 조건 |
|---|---|---|
| 동시 제출 100건 유실 | 7개 시나리오 모두 유실 0, 실패 0, 중복 채점 0 | 큐 꺼짐·켜짐, 제출 중 안전한 재시작·강제 종료(SIGKILL) 포함 |
| 제출 응답 시간 | p95 0.2~0.35초 | 채점을 기다리지 않고 바로 응답 |
| 100건 전체 채점 시간 | 동시 4건: 888초(분당 6.8건), 동시 8건: 450초(분당 13.3건) | 가짜 AI 호출 30초 × 채점 1건에 3번. 수정 전에는 호출 풀이 8개로 고정돼 동시 채점 수와 상관없이 분당 약 5.2건 |
| 재시작 복구 | 강제 종료 순간 채점 중이던 4건 모두 다시 채점 | 안전한 종료는 하던 채점을 마치고 내려감(잘린 채점 0) |

한계: 가짜 AI(실제 모델의 호출 한도·응답 편차 미반영), 로컬 16코어 PC, 1회 측정.

## 관리 규칙
- 차후 변경시에는 이 파일들을 갱신하는 것으로 한다. 문서는 여기서만 고치고, 코드 주석이 문서를 가리킬 때는 `pAIr-docs/평가/채점_기준표.md` 처럼 이 저장소 경로로 쓴다.
- 산출물은 "목표 설계"다. 지금 코드가 어디까지 왔는지는 [검증_결과.md](검증_결과.md)를 본다.
- 샘플 스크립트(`설계/erd/sample/`)는 이 저장소 최상위에서 실행한다. 예: `python 설계/erd/sample/make_sample.py`
