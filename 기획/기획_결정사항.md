# pAIr 기획 결정 사항

> 2026-11-18 정리. 애매했던 기획 요소를 질문으로 확정한 결과다. 구현과 ERD는 이 문서를 기준으로 맞춘다.
> **ERD 반영** 칸: ✅ 반영됨 · ⬜ 아직 반영 안 됨(후속 작업) · — DB 변경 없음

## 1. 실전 시험 (B2B)

| 항목 | 결정 | ERD 반영 |
|---|---|---|
| 응시자 가입 | 회원가입 없이 응시. 기록은 기업 쪽에만 남고 응시자의 "내 기록"에는 나오지 않는다 | ✅ attempts.user_id는 자가진단만 |
| 입장 방법 | **메일로 받은 개인별 입장 링크로만** 입장. 회차 공용 입장 코드는 없다. 링크는 기업이 등록한 대상자에게만 나가므로 명단에 없는 사람은 들어올 수 없다 | ✅ entry_code 삭제 |
| 링크 토큰 | 추측할 수 없는 무작위 값(`SecureRandom` 32바이트, Base64URL). **DB에는 SHA-256 해시만 저장**한다. DB가 유출돼도 링크를 만들 수 없다. 메일을 다시 보낼 때는 토큰을 새로 만든다(이전 링크는 무효) | ✅ invite_token_hash |
| 토큰 만료 | 시작 전에는 따로 만료 시각 없음. 회차 종료(`ends_at`)가 지나면 쓸 수 없다. **시험을 시작한 뒤에는 연결 유예(5분)를 넘기면 링크가 만료된다**(아래 "끊김·결시") | ✅ exam_participants.link_expired_at |
| 메일 발송 | 대상자 등록 즉시 1번, 시작 24시간 전 알림 1번 | ✅ invited_at, reminded_at |
| 대상자 등록 | 회차 만들기 화면에서, **사이트가 제공하는 양식에 맞춘 CSV 업로드**(이름, 이메일). 업로드 전에 중복·형식 오류를 미리 보여 준다. 올린 CSV 원본은 S3에 보관한다 | ✅ exam_sessions.participants_csv_key |
| 회차 과제 | 한 회차에 과제 여러 개. 응시자는 회차 시간 안에서 **과제를 자유롭게 오가며** 푼다 | ✅ exam_session_tasks |
| 시간 | 과제별 시간 없이 **회차 전체(시작~종료)**로 본다 | ✅ |
| 제출 | **과제별로 제출**한다. 종료 시각에 남은 과제는 자동 제출. 제출한 과제부터 채점을 시작한다 | — (attempts가 과제별 1건) |
| 후속 질문 | 실전에도 **과제마다** 후속 질문(설명 서술형)을 둔다. 회차 시간 안에 포함 | — |
| 감독 동의 | 대상자마다 회차당 1번 | ✅ proctor_consents PK = participant_id |
| 끊김·결시 | 종료 전이면 **같은 링크로 다시 들어와 이어서** 푼다. 끊긴 시간은 보전하지 않는다. 단 **마지막 연결 신호(10초마다) 뒤 5분(유예) 안에** 돌아와야 한다. 90초 넘게 끊겼다 돌아오면 `CONNECTION_LOST`, 5분을 넘기면 링크가 만료되고 `LINK_EXPIRED` 가 남는다(자동 탈락 아님, 담당자가 확인). 결시자는 새 회차에 다시 초대한다 | ✅ last_seen_at, link_expired_at, 이벤트 유형 2개 (2026-11-21) |
| 결과 공개 | 응시자에게는 **보여 주지 않는다**(제출 완료 안내만). 결과는 기업만 본다 | — |
| 기업이 보는 결과 | 대상자별 리포트(6개 역량 점수, 근거 턴, 감독 주의 구간), 회차 안 **순위와 역량별 분포** | — (조회로 계산) |
| 회차 수정·취소 | **시작 전까지만** 시간·과제·대상자 수정과 취소 가능(변경 시 대상자에게 메일). 시작 후에는 바꿀 수 없다 | ✅ exam_sessions.canceled_at(시작 전만) |
| 보관 기간 | 감독 스냅샷은 회차 종료 **7일** 뒤 자동 삭제(동의 문구와 같음. 서버 설정값은 코드 기본값·`application.yml` 모두 아직 30이라 변경 필요)(`snapshot_deleted_at`). **확정(2026-11-23, 구현 전)**: 삭제 예정 2일 전부터 감독관·매니저가 7일씩 최대 2번(총 21일) 연장할 수 있고 이력을 남긴다 → 동의 문구도 이에 맞춰 바꿔야 한다 응시·채점 기록은 **1년** | ✅ snapshot_deleted_at |
| 이벤트 증거 구간 (확정 2026-11-23, 구현 전) | 이벤트 앞 8초·뒤 4초(시간 기준, 최대 24장)의 PC 웹캠·휴대폰 사진을 응시자 PC 가 로컬에 두었다가 이벤트 때만 올려 파일 저장소에 저장한다. 감독관·매니저가 완료된 회차에서도 확정/기각한다. 연속 녹화·영상 스트리밍·서버 추론은 하지 않는다. 휴대폰 보조 캠은 영상 대신 JPEG 프레임 서버 중계로 다시 켠다(분석은 응시자 PC Worker). 근거: [docs/intent/이벤트-증거구간-검토-보관연장.md](../docs/intent/이벤트-증거구간-검토-보관연장.md) | ⬜ 설계만 |
| 판정 | 감독 이벤트는 자동 탈락이 아니라 담당자가 확인(OK/SUSPECT)하는 기록 | ✅ |
| 감독 분석 위치 | 영상은 서버로 보내지 않고 **응시자 PC 에서 분석**한다. 이상 순간의 이벤트와 사진 1장만 서버로 보낸다(휴대폰 보조 캠을 켜면 휴대폰은 영상만 송신하고 PC 가 분석). 브라우저 이벤트(탭·창·마우스·전체화면 이탈, 외부 붙여넣기)는 모델 없이 바로 기록한다 | — |
| 입장 마감 | **없다.** 시작 전이면 언제든 입장해 환경 점검을 하고 대기한다. (한때 감독 회차에 "시작 10분 전 마감"을 뒀으나 2026-11-21 에 없앴다. 초대 메일은 "시작 전에 미리 입장해 점검을 마쳐 주세요"라고 안내만 한다) | — |
| 환경 점검 | PC(브라우저·원격·모니터·카메라·소음·조명·얼굴 위치·귀·손목). 방 360도 스캔은 뺐다. 휴대폰 점검(조명·책상 위)은 휴대폰 캠 스위치가 꺼져 있는 동안 나오지 않는다. **점검 결과가 실패·경고여도 응시를 막지 않는다**(2026-11-22). AI 모델이 틀릴 수 있어서 결과를 저장하고 입장하게 하며, 실패한 채 입장한 기록은 감독 기록에 남겨 감독관이 확인한다. 책상 위에서 휴대폰·책·화면이 감지돼도 경고만 한다(사진은 감독관에게 전달, 판단은 감독관). 점검 진행 상태는 3초마다 서버에 올라가 콘솔의 대상자 상세 점검 카드에서 실시간으로 볼 수 있다 | ✅ env_scan_photos, env_check_progress |
| 감독 연결 필수 | **현재 정책(2026-11-23): 웹캠 + PC 화면 공유 두 채널이 연결돼야** 응시를 시작한다. 시험 중 하나라도 끊기면 **15초 유예** 뒤 응시 화면을 막고, 모두 돌아오면 이어서 응시한다. 서버의 연결 유예(5분)와는 별개다. 휴대폰 보조 캠은 프론트 스위치(`PHONE_CAM_ENABLED=false`)로 꺼 두었다(11-21 중단, 휴대폰 영상은 LTE 등에서 TURN 서버가 필요해 보류). 화면 공유(`SCREEN_SHARE_ENABLED`)는 11-21 에 함께 꺼졌다가 웹캠만으로는 탐지 범위가 좁아 11-23 에 다시 켰다. 휴대폰까지 포함한 세 채널 규칙은 코드에 남아 있어 스위치를 켜면 동작한다 | — |
| 화면 공유 | 동의 후 "전체 화면" 공유(창·탭만 공유하면 시작 불가). 영상은 녹화·저장·분석하지 않고, 이벤트 순간 글자를 읽을 수 없게 흐린 사진 1장만 남긴다. **서버가 아직 화면 공유 이벤트(`SCREEN`)를 받지 않아 전송은 꺼져 있다** | ⬜ 백엔드 `SCREEN` 출처·유형 |
| 사전 테스트 | `/practice` 에서 실제와 같은 점검(웹캠·화면 공유)을 해 본다. 서버에 이벤트·사진·점검 결과를 남기지 않는다. 시험 7일 전부터 여는 제한은 가정이며 지금은 공개 페이지로 언제든 열린다 | — |
| 감독관 영상 보기 | 감독관이 응시자를 **열었을 때만** 웹캠·화면 영상(휴대폰 캠을 켜면 휴대폰 영상도)을 P2P 로 보낸다(저장 없음, 응시자 1명당 감독관 최대 2명). 개발 릴레이로만 동작하고 운영 백엔드는 아직 없다 | — |
| 늦은 입장 | 시작 시각이 지나도 종료 전이면 입장·환경 점검·동의 뒤 시작할 수 있다. 늦은 시간은 보전하지 않는다(종료 시각은 그대로) (2026-11-21) | — |
| 새로고침 | 시작한 응시자가 링크로 다시 들어오면 대기실에서 웹캠을 다시 연결해 이어 간다. 5분 유예를 넘기면 링크가 만료된다 | — |
| 응시자 안내 메시지 | 감독관이 콘솔에서 응시자에게 **일방향 안내**(자유 입력, 최대 500자)를 보낼 수 있다. 응시자 화면에 시험을 막지 않는 배너가 뜨고 "확인"을 누르면 읽음 시각이 남는다. 취소·종료된 회차에는 보낼 수 없고, 응시자는 끝난 뒤에도 받은 안내를 읽을 수 있다. 답장·정해진 문구 목록은 없다 (2026-11-22) | ✅ proctor_notices |
| 감독 콘솔 알림 | 새 감독 이벤트가 들어오면 알림음(켜기·끄기는 브라우저에 저장)을 내고 감독관이 확인할 때까지 새 이벤트를 모아 보여 준다. 응시자 영상은 눌러서 크게 볼 수 있다 (2026-11-23) | — |
| 이상 판정 | 정밀 분석(OWL-ViT)은 기준값을 어떻게 조정해도 너무 빡세거나 허술해 **자동 판정을 없앴다**. 귀·손목·책상 위 사진은 감독관이 직접 확인한다 (2026-11-20) | — |
| 감독 분석 부하 | 시험 화면이 끊기지 않도록 웹캠 분석을 초당 10회 이하로 제한하고 모델을 번갈아 돌린다. 감지 규칙은 모두 1초 이상 지속돼야 경고하므로 감지에는 영향이 없다 | — |
| HTTPS 인증서 | 개발 서버의 자체 서명 인증서 경고("안전하지 않음")는 개발 한정이며, 정식 도메인·인증서로 배포한 뒤 다시 검증한다 (2026-11-21 결정) | — |

## 2. 과제

| 항목 | 결정 | ERD 반영 |
|---|---|---|
| 과제 용도 | 과제마다 **용도 하나**: 자가진단용(`SELF`) 또는 기업용(`LIVE`). 기업용 과제는 자가진단 목록에 절대 나오지 않아 문제가 새지 않는다 | ✅ tasks.usage + 응시 모드와 복합 FK |
| 기업용 과제 | 관리자가 **아주 많이** 만들어 두고, 기업 담당자가 그중에서 골라 회차에 건다 | ✅ exam_session_tasks 복합 FK |
| 과제 공유 | 기업용 과제는 **모든 기업이 공유**한다(한 기업 전용 아님) | — (tasks.company_id 두지 않음) |
| 상태 | `OPEN` 공개·응시 가능 / `CLOSED` 목록에만 보이고 응시 막힘 / `HIDDEN` 숨김(초안·검수 대기, 기본값). 회차에는 `OPEN`만 걸 수 있다(2026-11-18 팀 DDL과 머지) | ✅ |
| 관리 상태 | 관리자 화면은 과제를 **세 가지**로 관리한다(2026-11-20). **자가진단** = `OPEN` + `SELF`(누구나 자가진단에서 풂), **실전** = `OPEN` + `LIVE`(실전 시험 회차 전용, 자가진단에 보이면 유출), **검수 전** = `HIDDEN`(어디에도 안 보임). 화면 표기는 2026-11-23에 "공개 문제/비공개 문제"에서 "자가진단/실전"으로 바꿨다. 과제 하나는 한쪽에만 쓰고, 자가진단 과제를 복사해 실전 과제로 쓰지 않는다. 용도는 검수 전일 때만 바꿀 수 있다. `CLOSED`는 자가진단 과제를 내릴 때만 쓴다 | ✅ 칼럼 추가 없음(status + usage) |
| AI 문제 생성 | 관리자가 **글로만 정의**(직군, 난이도, 주제, 함정, 용도 등 폼 입력)하면 AI가 생성해 `HIDDEN`(검수 전)으로 저장, 관리자가 검토 후 공개. 자동 확인을 끝내 통과하지 못한 과제도 검수 전으로 저장하고 실패를 표시한다(어디에도 안 보이므로 안전). 비개발 자료는 PDF로 만든다. 참고 파일 업로드는 없다. 생성 기록 테이블은 두지 않는다. 설계: [AI_과제_생성_설계.md](../설계/AI_과제_생성_설계.md) | ✅ |
| 자가진단 과제 선택 | 목록에서 직군·난이도·시간으로 걸러 **직접 고른다**. 같은 과제 재응시 가능 | — |

## 3. 자가진단과 크레딧

| 항목 | 결정 | ERD 반영 |
|---|---|---|
| 과금 방식 | **크레딧**. 크레딧이 있어야 응시를 시작할 수 있다 | ✅ credit_ledger |
| 크레딧 얻기 | **가입 시 무료 지급** + **크레딧 단품 구매** | ✅ SIGNUP, PURCHASE |
| 크레딧 쓰기 | **응시 시작**(채점 1회 비용 포함), **롤백 1회**, **AI 채팅 턴 1회**마다 정해진 양을 쓴다. 양은 설정값으로 둔다 | ✅ ATTEMPT_START, ROLLBACK, CHAT_TURN |
| 재응시 | 같은 과제를 다시 풀어도 **새 응시와 같은** 크레딧 | — |
| 부족할 때 | 응시 중 크레딧이 바닥나면 **AI 채팅만 막는다**. 코드 편집과 제출은 된다. 채점은 응시 시작 때 이미 냈으므로 항상 된다 | — |
| 기록 | 적립·차감 한 건마다 **원장 행**(사유, 응시 ID, 양, 시각)으로 남긴다. 잔액은 원장 합계(필요하면 회원에 캐시). 동시에 여러 번 차감돼도 음수가 되지 않게 잠금 처리 | ✅ balance_after >= 0 |
| 롤백 횟수 | 제한 없음(크레딧으로만 제한) | — |
| 결제 | 크레딧 구매 결제는 테스트 결제(결제 대행사 테스트 모드)로 구현 | ✅ credit_purchases |

## 4. 기업 계정

| 항목 | 결정 | ERD 반영 |
|---|---|---|
| 가입 흐름 | **도입 문의 → 관리자 승인 → 초대**. 기업이 문의 폼을 내면 관리자가 승인하면서 회사를 등록하고 담당자에게 초대 메일을 보낸다. **초대 링크로만** 담당자 계정을 만들 수 있다(자체 가입 없음) | ✅ company_inquiries, company_invites |
| 소속 | **한 사람은 한 회사에만** 속한다. 그래서 팀 DDL의 company_members(회원↔회사 다대다) 대신 회원에 소속 회사를 바로 둔다(`users.company_id`, MANAGER·PROCTOR만 값이 있고 CHECK로 강제). 회사 정보 자체는 companies에만 있다 | ✅ users.company_id |
| 회사 정보 | 이름, 사업자번호, 연락처, 직원 명단 파일(S3 키) | ✅ companies.contact, employee_list_path |
| 담당자 수 | 한 회사에 **여러 명**. 관리자가 같은 회사에 담당자를 추가로 초대할 수 있고, 모두 그 회사의 회차를 함께 본다 | ✅ users.company_id |
| 기업 권한 | 기업 회원은 두 가지: **`MANAGER`**(회차 만들기, 기업용 과제 고르기, 대상자 등록, 결과 보기, 감독관 초대, **감독도 가능**)와 **`PROCTOR`**(감독관: 감독 화면과 감독 이벤트 판단만). 관리자가 첫 매니저를 초대하고, 매니저가 자기 회사 감독관을 초대한다 | ✅ users.role, company_invites.role |
| 회사 데이터 분리 | 담당자는 자기 회사 회차·대상자·결과만 본다 | ✅ |
| 로그인·권한(Spring Security) | 회원 테이블 한 줄로 로그인 정보가 끝난다. 권한 = `ROLE_` + role(USER/MANAGER/PROCTOR/ADMIN). **RoleHierarchy `ROLE_MANAGER > ROLE_PROCTOR`**로 매니저가 감독 권한을 자동으로 가진다. `member_status = 'ACTIVE'`일 때만 로그인 가능(isEnabled). 회사 데이터 분리는 권한과 별개로, 로그인 정보에 넣은 companyId와 회차의 company_id를 비교해 막는다. 기업 회원 테이블을 따로 두지 않는다(조인·코드만 늘어남) | ✅ 테이블 변경 없음 |
| 기업 과금 | **기획만** 하고 구현하지 않는다(예: 응시자 1명당 과금). 승인된 기업은 무료로 쓴다 | — |
