## 1. 개요

pAIr에서 **응시자가 제출한 뒤부터 리포트가 나오기까지의 흐름**을 담당합니다.

제출된 응시를 서로 다른 회사의 LLM 두 개로 채점하고, 6개 역량 점수와 감점 근거를 리포트로 보여 줍니다. 비개발 과제는 제공 자료를 RAG로 줄여 채점 비용을 낮춥니다. 관리자가 쓰는 AI 과제 생성과 채점 실험 툴도 맡습니다.

| 구분 | 내용 |
| --- | --- |
| 담당 흐름 | 채점 큐에서 꺼냄 → 이중 판정 + RAG → 리포트 → 대시보드 |
| 대표 기능 | LLM 이중 판정 채점, RAG |
| 맡는 테이블 | 채점 기준·결과 10개, 문항 6개, 문서 2개 (총 18개) |
| 핵심 목표 | 반복 채점 편차 3점 이내, 응시 1건 채점 $0.05 이하, 채점 2분 이내 |

## 4. 구조 설계

### 채점 흐름

```
제출 (팀원 3·4)
  → 채점 큐 (팀원 1, Redis)
  → ScoringService.evaluate()
      1. 자동 체크 (AUTO)
         - AI 사용 여부 (U0, C0, K0, J0)
         - 숨은 테스트 실행 (D0~D3, 개발 과제)
         - 첫 유효 결과 시간 (D5)
      2. 판정 입력 만들기
         - 고정 앞부분: 과제, 정답, 체크 기준 (캐시 대상)
         - 본문: 대화 기록, 작업 파일, 후속 답변, 이벤트 요약
         - 비개발: 제공 자료 (통째로 또는 RAG 조각)
      3. 두 모델 동시 호출 (ClaudeJudge, OpenAiJudge)
      4. 판정 합치기 (combine)
         - 두 모델 모두 걸림 → 전액 감점
         - 한쪽만 걸림 → 절반 감점 (판정 엇갈림)
         - 근거 턴이 없는 감점 → 무효
  → 리포트
```

한 모델 호출이 실패하면 남은 한쪽으로만 판정합니다.

## 5. 주요 기능 명세

### 5.1 채점 기준

6개 역량, 총 100점입니다. 각 역량은 감점 체크 항목으로 구성합니다.

| 역량 | 배점 | 체크 |
| --- | --- | --- |
| AI 활용력 | 20 | U0~U7 |
| AI 통제력 | 15 | C0~C4 |
| 문제 분해력 | 10 | K0~K3 |
| 위임 판단력 | 10 | J0~J3 |
| AI 결과 도출력 | 30 | D0~D5 |
| 성과 잠재력 | 15 | P1~P4 |

- **AUTO 체크:** 코드로 판정합니다. AI 미사용, 숨은 테스트 결과, 테스트 추가 여부, 첫 유효 결과 시간이 해당합니다.
- **JUDGE 체크:** 채점 모델이 판정합니다. 체크마다 판정 기준 문장(`judgeHint`)이 있습니다.
- **과제 유형별 기준:** D1~D4는 개발(DEV)과 비개발(BIZ)의 기준이 다릅니다.
- **AI 미사용 처리:** AI를 쓰지 않은 응시는 통제력·분해력·위임 판단력을 0점 처리합니다. 판정 없이 만점을 받는 것을 막기 위함입니다.

### 5.2 이중 판정 채점

- 두 모델에 같은 입력을 주고 동시에 호출합니다.
- 모델은 체크마다 `violated`, `count`, `evidence`(근거 턴), `reason`을 JSON으로 답합니다.
- 점수는 LLM이 직접 매기지 않습니다. 모델은 "걸렸는지"만 정하고, 감점 크기는 코드가 정합니다.
- 총점은 저장하지 않고 체크 결과의 감점으로 계산합니다(배점 − 감점 합).

**두 회사 모델을 쓰는 이유:** 두 회사 모델은 서로 다른 칸에서 틀립니다. 프롬프트 v6에서는 두 모델이 함께 틀린 칸이 0개였고, 틀린 칸은 모두 한쪽만 틀려 절반 감점으로 끝났습니다. 한쪽 모델에 장애가 나도 남은 모델로 채점할 수 있습니다.

다만 terra 혼자의 정확도(99.4~99.6%)가 Haiku보다 높아, terra 단독 채점이 더 나을 가능성이 있습니다. 비용과 장애 대비를 함께 따져 다시 검토합니다.

### 5.3 RAG (비개발 채점 자료)

```
PDF → 페이지 텍스트 추출 (PDFBox)
    → 쪽 단위 조각 (숫자 표·CSV는 통째로)
    → 임베딩 (text-embedding-3-small)
    → 제출물 문장으로 과제 안에서 검색 (B-tree + 정확 검색)
    → 근거 조각만 채점 프롬프트에 넣기
```

- 설정 `pair.judge.reference-docs`로 `full`(통째로)과 `rag`를 고릅니다.
- 검색은 항상 과제 하나 안에서만 합니다. 조각이 수십 개라 근사 검색(HNSW)이 필요 없습니다.
- HNSW는 과제로 거르면 결과가 0개가 되는 문제를 확인해 쓰지 않습니다.

### 5.4 AI 과제 생성

```
관리자 폼 (직군, 난이도, 주제, 함정)
  → gpt-6.1-terra 구조화 출력
  → 자동 확인
  → HIDDEN으로 저장
  → 팀원 4 과제 콘솔에서 검수 후 OPEN
```

| 과제 유형 | 생성 결과 | 자동 확인 |
| --- | --- | --- |
| 개발 | 시작 코드, 공개 테스트, 숨은 테스트, 정답 | 시작 코드 컴파일·공개 테스트 통과, 숨은 테스트가 시작 코드에서 실패, 정답은 전부 통과, 30초 이내 |
| 비개발 | 자료 CSV·문서, 숨은 체크리스트, 함정과 근거 문장, 객관식·단답형 문항 | 형식, CSV 칸 수, 단답형 정답 재계산, 함정 근거 문장이 자료에 있음, 다른 회사 모델이 풀어 전부 정답 |

난이도와 설명 품질은 자동 확인으로 알 수 없어 관리자 검수로 봅니다.

### 5.5 채점 툴

- 체크별 판정 기준 문장을 고친 새 프롬프트 버전을 만듭니다. 저장한 버전은 고치지 않습니다.
- 같은 응시를 여러 번 채점해 편차와 비용을 비교합니다.
- 실제 채점에 쓸 버전을 활성화합니다(현재 v6).
- 반복 실험은 Batch API로 돌려 비용을 50% 줄입니다.

## 7. 기술 선택 근거

| 결정 | 선택 | 근거 |
| --- | --- | --- |
| LLM 연동 | Spring AI | 두 회사 모델·임베딩·구조화 출력을 한 방식으로 사용 |
| 채점 방식 | 두 회사 모델 이중 판정 | v6에서 두 모델이 함께 틀린 칸 0개. 한쪽만 틀리면 절반 감점이라 오차가 반으로 줄어듦 (terra 단독 재검토 필요) |
| 점수 산출 | 체크 판정 + 코드 감점 | 같은 v4 프롬프트로 5회 총점 차이 평균 1.4~3.1점 (점수 직접 5.3점), 기대 총점 오차 1.8~2.3점 (점수 직접 4.6점) |
| 출력 형식 | JSON Schema | 파싱 실패 0/35 |
| 채점 모델 | Haiku 5.5 + terra | 상위 모델(Sonnet, sol)과 정확도가 같은 수준, 비용 약 1/4 |
| 벡터 DB | pgvector | 과제 안 수십 조각만 비교. 서버 추가 없이 과제 데이터와 한 트랜잭션 |
| 임베딩 | 3-small | 상위 3개 적중 19/20, 3-large보다 저렴 |
| 문서 조각 | 쪽 단위 | 19/20 (200자 고정은 13/20) |
| 비용 절감 | 실제 채점은 캐시만 | Batch는 결과가 늦어 "채점 2분 이내"를 지킬 수 없음 |

## 8. 검증 결과

프롬프트 v6, 샘플 응시 7개 × 5회 기준입니다.

| 항목 | 기준 | 결과 | 판정 |
| --- | --- | --- | --- |
| 채점 일관성 | 5회 총점 차이 3점 이내 | 평균 2.6~2.9점, 최대 7~9점 (7개 중 4~5개만 3점 이내) | ⚠️ |
| 두 모델 차이 | 판정 엇갈림 15% 이하 | 1.7~2.3% | ✅ |
| 채점 정확도 | 정답표 일치 90% 이상 | Haiku 98.1~98.8%, terra 99.4~99.6% | ✅ |
| 응답 속도 | 채점 2분 이내 | 26초 | ✅ |
| 비용 | 응시 1건 $0.05 이하 | $0.018 | ✅ |
| RAG 채점 | 입력 토큰 50% 절감, 총점 차이 3점 이내 | 토큰 60~76% 절감, 비용 −47%, 자료를 보는 체크 차이 0~2점 | ✅ |
| AI 과제 생성 | 10개 중 8개 이상 바로 사용 | 개발 10/10 ($0.016, 38초), 비개발 10/10 ($0.04, 66초) | ✅ |

**채점 일관성이 기준에 못 미친 이유:** 판정 기준 문장을 v6까지 고쳐 정확도는 올랐지만, 흔들림은 줄지 않았습니다. 한 모델만 "걸림"이라고 하면 절반 감점이 되어, 회차마다 총점이 2~3점씩 오르내립니다. 기준 문장보다 모델이 매번 조금씩 다르게 답하는 것이 원인이라, 문장 수정만으로는 더 줄이기 어렵습니다.

자세한 실험 조건은 [기술검증_보고서_정현.md](기술검증_보고서_정현.md)에 있습니다.
