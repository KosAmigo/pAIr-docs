# 자가진단 과제별 랭킹 시스템 기획안

> 작성일: 2026-11-28  
> 상태: 기획 확정안 · 2026-11-28 사용자 검토 반영

## 1. 배경과 목표

pAIr 자가진단은 과제를 제출하면 채점 리포트와 역량별 피드백을 제공하고, 사용자는 결과를 복기한 뒤 같은 과제를 다시 풀어 점수를 높일 수 있다. 이 흐름을 활용해 사용자 간 건전한 경쟁과 개인의 성장을 함께 돕는 과제별 랭킹을 제공한다.

랭킹은 같은 자가진단 과제를 완료한 사용자끼리 비교한다. 기업 실전 시험(`LIVE`)의 응시와 결과는 랭킹 데이터에 포함하지 않는다.

## 2. 제품 원칙

- **비교 기준을 좁힌다.** 첫 버전은 과제별 랭킹만 제공한다. 서로 다른 과제의 점수를 합쳐 전체 사용자를 한 줄로 세우지 않는다.
- **성장을 보인다.** 랭킹과 함께 본인의 이전 점수, 최고점, 최근 점수 변화 등 성장 정보를 연결한다.
- **복기는 순위 점수와 분리한다.** 복기 횟수는 참고 정보로 작게 표시하며 점수나 순위 계산에 사용하지 않는다.
- **공개 범위는 사용자가 정한다.** 랭킹 참여는 기본 비공개이며, 사용자가 공개에 동의한 경우에만 다른 사용자에게 표시한다. 표시 이름은 회원가입 때 정하는 고유 닉네임이다.
- **랭킹 산정은 서버가 책임진다.** 점수, 제출 시각, 응시 소유자를 서버 데이터로 확인하고 프론트에서 순위를 계산하지 않는다.

## 3. MVP 범위

### 포함

- `SELF` 자가진단의 과제별 랭킹
- 유효한 채점 리포트의 총점(100점 기준)을 이용한 순위
- 점수가 같으면 공동 순위로 표시
- 점수 백분위에 따른 티어 표시
- 사용자별 복기 횟수 표시
- 내 순위와 점수 추이 확인
- 랭킹 공개 참여 설정 (기본 비공개)
- 회원가입 시 중복을 허용하지 않는 닉네임 설정

### 제외

- 기업 실전 시험(`LIVE`) 결과
- 서로 다른 과제를 합산한 종합 랭킹 또는 직군별 통합 레이팅
- Elo와 같이 사용자 간 대결 결과를 입력으로 요구하는 레이팅 방식
- 기업 담당자가 조회하는 자가진단 랭킹·기록

## 4. 랭킹 산정 규칙

### 4.1 대상 점수

- 동일한 과제 ID 안에서 비교한다. 과제가 수정되어 복제된 경우 별도 과제로 취급한다.
- 공식 점수는 채점 리포트의 `report.total`(100점 기준)을 사용한다. 문항 점수가 별도로 제공되는 경우 MVP에서는 합산하지 않는다.
- 리포트가 완료 상태이고 랭킹 계산에 필요한 총점이 존재하는 응시만 대상으로 한다. 채점 실패, 채점 중, 총점이 없는 구버전 리포트는 제외한다.

### 4.2 재응시 반영

사용자의 해당 과제 최고 유효 점수를 랭킹 점수로 사용한다. 복기 후 재응시해 최고점을 갱신하면 순위가 올라갈 수 있고, 기존 최고점보다 낮은 결과가 나와도 그동안의 성취가 사라지지 않는다. 같은 최고 점수의 응시가 여러 개면 최근 완료 기록을 대표 기록으로 표시한다.

최고점 기록의 선택 기준은 다음과 같다.

1. 점수가 높은 응시
2. 점수가 같으면 최근에 완료한 응시를 대표 기록으로 표시한다. 이 선택은 기록 갱신일에만 영향을 주고 랭킹 순위에는 영향을 주지 않는다.

이 방식은 재응시가 많은 사용자에게 기록을 갱신할 기회를 준다. 대신 반복 응시로 과제에 익숙해지는 효과가 있으므로, 랭킹을 실력의 절대적·공정한 측정치로 표현하지 않고 “해당 과제에서 등록된 최고 기록”으로 설명한다. 필요하면 시즌제, 첫 응시 랭킹 또는 응시 횟수 제한을 별도 후속 정책으로 검토한다.

### 4.3 동점 처리

- 순위는 총점 내림차순만으로 정한다. 문제를 푼 시간은 순위, 티어, 참여 자격에 영향을 주지 않는다.
- 같은 점수인 사용자는 공동 순위로 표시한다. 예를 들어 점수 순서가 100점, 90점, 90점, 80점이면 순위는 1위, 2위, 2위, 4위다.
- 풀이 시간은 랭킹 목록에 표시하지 않는다. 개인 성장 화면에서 풀이 시간 정보를 제공하는 경우에도 랭킹과 무관한 참고 정보로 취급한다.

### 4.4 티어와 인원 비율

랭킹 참여자 중 해당 과제의 유효한 최고 기록을 보유한 사용자를 모집단으로 삼고, 점수 순위의 백분위로 티어를 부여한다. 첨부 예시에서 제외한 그랜드 마스터·에메랄드·아이언의 비율을 빼고 남은 티어의 비율 합계(83.02%)를 100%로 정규화한 제안은 다음과 같다.

| 티어 | 목표 인원 비율 | 누적 상위 비율 |
|---|---:|---:|
| 챌린저 | 0.01% | 상위 0.01% |
| 마스터 | 1.12% | 상위 1.13% |
| 다이아몬드 | 5.02% | 상위 6.15% |
| 플래티넘 | 22.43% | 상위 28.58% |
| 골드 | 28.14% | 상위 56.72% |
| 실버 | 25.03% | 상위 81.75% |
| 브론즈 | 18.25% | 나머지 |

- 티어는 과제별로 계산한다. 다른 과제의 점수나 티어는 합산하지 않는다.
- 인원 비율은 목표치다. 참여자가 적으면 챌린저 등 상위 티어가 비어 있을 수 있으며, 목표 비율을 맞추려고 사용자를 강제로 배정하지 않는다.
- 같은 점수로 경계에 걸린 사용자는 나누지 않고 같은 티어를 부여한다. 따라서 동점자가 많은 경우 실제 인원 비율은 목표치와 달라질 수 있다.
- 공개 랭킹 티어는 공개 참여자를 기준으로 계산한다. 비공개 사용자는 자신의 점수 위치와 티어를 본인 화면에서 확인할 수 있지만 공개 목록과 공개 집계에는 들어가지 않는다.
- 티어 분포는 사용자 수가 적은 과제에서 변동성이 크므로, 실제 참여 규모를 확인하고 출시 후 조정할 수 있다.

### 4.5 복기 횟수

- 복기 횟수는 해당 사용자가 해당 과제에서 만든 롤백 분기 응시 수로 집계한다. 현재 구조에서는 `forked_from_checkpoint_id`가 설정된 후속 응시를 복기 분기로 볼 수 있다.
- 롤백 횟수는 점수·정렬·참여 자격에 영향을 주지 않는다.
- 랭킹 목록에서는 이름 옆에 작은 보조 정보(예: `복기 3회`)로 표시한다. 개인 상세에서는 횟수의 의미를 설명한다.
- API 구현 전에 `forked_from_checkpoint_id`가 롤백 1회마다 생성되는 응시를 정확히 나타내는지 코드 동작과 대조한다.

### 4.6 랭킹 시즌과 과거 결과

랭킹은 2주 또는 3주 단위 시즌으로 운영하고, 시즌이 끝날 때 다음 시즌 랭킹을 새로 시작한다. 주기 선택은 참여자 규모를 고려해 확정한다. 초기에는 과제별 티어 분포를 안정시키기 위해 3주 시즌을 권장한다. 시즌 안의 주차별 점수 흐름과 종료된 시즌 결과를 다시 볼 수 있게 한다. 시즌이 초기화되어도 개인의 전체 기간 최고 점수와 성장 이력은 별도로 보존한다.

- 시즌 랭킹에는 해당 시즌에 제출한 자가진단 응시만 반영한다. 이전 시즌 점수는 새 시즌의 점수·순위·티어에 포함하지 않는다.
- 시즌은 한국 시간 기준 월요일 00:00에 시작하고, 선택한 2주 또는 3주 뒤 월요일 00:00 직전에 끝나는 안을 제안한다.
- 점수가 늦게 채점될 수 있으므로 제출 시각으로 시즌을 정하고, 시즌 종료 후 채점 완료 유예 시간을 둔 뒤 결과와 보상을 확정한다. 유예 시간은 운영 채점 지연을 확인해 정한다.
- 같은 사용자가 시즌 중 같은 과제를 여러 번 풀면 그 시즌의 최고 점수만 랭킹에 사용한다. 다음 시즌에는 이전 점수가 이월되지 않고, 새 시즌에 제출한 응시만으로 다시 경쟁한다.
- 확정된 시즌 결과는 보관해 사용자가 시즌별 순위, 티어, 점수와 복기 횟수를 다시 볼 수 있게 한다. 시즌 안의 주차별 점수 흐름도 개인 성장 화면에서 확인할 수 있게 한다. 점수 정정이 필요하면 확정 후 자동 재산정하지 않고 운영 정정 절차를 둔다.
- 시즌 결과는 나중에 다시 계산해도 같은 결과가 나오도록 시즌 식별자와 확정 결과를 저장한다. 구현 시 응시 원본을 기준으로 결과를 재생성할 수 있게 한다.
- 공개 랭킹 참여는 기존과 동일하게 사용자 동의가 필요하다. 과거 시즌 공개 기록을 보관·노출하는 기간과 공개 철회 시 과거 기록 처리 방식은 출시 전에 결정한다.

### 4.7 티어별 크레딧 보상 검토안

티어 달성 보상으로 크레딧을 지급하면 재응시와 복기를 돕고, 크레딧의 쓰임을 경험하게 할 수 있다. 다만 시즌·과제별로 보상이 중복 누적되면 크레딧 경제가 흔들리거나 쉬운 과제에서 보상을 반복 수령할 수 있어 다음 방식으로 시작하는 것을 제안한다.

- 보상은 시즌이 끝난 뒤 최종 티어를 확정하고 한 번 지급한다.
- 사용자가 여러 과제의 랭킹에 참여해도 보상은 시즌당 1회만 받는다. 해당 시즌에 달성한 티어 중 가장 높은 티어를 보상 기준으로 삼는다.
- 티어별 보상 크레딧은 상위 티어일수록 많게 설정하되, 실제 크레딧 비용과 응시·채팅 소비량을 확인해 금액을 정한다. 시즌 지급 상한과 월간 총 발행량도 둔다.
- 시즌 유효 참여자가 적은 과제에서는 백분위 티어와 보상이 크게 흔들릴 수 있다. 과제별 최소 참여 인원을 충족하지 못하면 랭킹은 보여 주되 티어 보상은 지급하지 않는 방안을 검토한다.
- 순위 조작·중복 지급을 막기 위해 보상은 사용자·시즌별 멱등 처리하고 지급 내역을 크레딧 원장에 남긴다.

이 절은 2~3주 주기 초기화와 이전 시즌 점수 미반영을 반영한 기획 방향이다. 3주 시즌은 초기 운영 권장안이며, 2주와 3주 중 최종 주기는 참여 규모와 재참여율을 보고 확정한다. 크레딧 보상 규칙과 지급 규모도 아직 제안 단계이며 파일럿에서 참여 규모와 크레딧 사용 영향을 확인한 뒤 확정한다.

### 4.8 랭킹 산정의 두 번째 안: Elo 기반 시즌 레이팅

현재 1안은 과제별 최고 점수로 과제별 순위를 만들고, 각 과제 참가자 분포로 티어를 부여한다. 2안으로는 여러 과제의 결과를 하나의 시즌 레이팅으로 합치는 Elo 기반 방식을 검토할 수 있다. 이 방식에서는 사용자에게 익숙한 단일 시즌 점수로 전체적인 성장과 순위를 보여줄 수 있다.

일반적인 Elo는 상대의 레이팅으로 기대 점수를 계산하고 실제 결과와의 차이만큼 레이팅을 조정한다. FIDE 규정도 기대 점수와 실제 점수의 차이에 따라 레이팅 변화를 계산하며, 경기 결과를 분수 점수로 다룬다([FIDE Rating Regulations, §8](https://handbook.fide.com/chapter/B022024)). pAIr에는 직접 대결 결과가 없으므로 다음처럼 과제 난이도를 상대 레이팅으로 쓰는 **Elo 응용안**이 필요하다.

- 사용자 레이팅과 과제 난이도 레이팅의 차이로 기대 점수 `E`를 계산한다.
- 표준 기대 점수 식을 응용하면 `E = 1 / (1 + 10^((R_task - R_user) / 400))`로 둘 수 있다. 여기서 `R_user`는 사용자 레이팅, `R_task`는 과제 난이도 레이팅이다.
- 채점 총점을 실제 점수 `S`로 환산한다. 초안 환산식은 `S = report.total / 100`이다.
- 응시 결과마다 `새 레이팅 = 기존 레이팅 + K × (S - E)` 형태로 조정한다. 초기 레이팅, K 값, 과제 난이도 레이팅 산정 방식은 파일럿 데이터로 보정한다.
- 전주 결과가 다음 시즌에 반영되지 않도록 시즌마다 같은 초기 레이팅에서 시작한다. 과거 시즌의 Elo 레이팅은 다음 시즌 시작값으로 이월하지 않는다.
- 티어 비율은 시즌 종료 시점의 Elo 레이팅 분포에 적용한다. 티어 보상도 같은 최종 분포를 기준으로 계산할 수 있다.
- 재응시 점수 부풀리기를 막으려면 같은 사용자·과제의 시즌 내 응시를 여러 번 각각 반영하지 않고, 해당 과제의 최고 유효 기록 하나만 반영하는 방식을 검증한다.

**장점:** 과제 난이도 차이를 보정해 여러 과제의 결과를 시즌 종합 레이팅으로 묶을 수 있고, 점수가 기대보다 높은 과제에서 더 큰 레이팅 상승을 줄 수 있다.

**비용과 위험:** 과제별 난이도 레이팅과 충분한 응시 데이터가 필요하다. 채점 기준이나 과제 버전이 바뀌면 난이도 보정을 다시 확인해야 한다. 사용자가 점수만 보고 등락 이유를 이해하기 어려울 수 있고, 재응시를 반영하는 순서에 따라 결과가 달라질 수 있어 설명과 재현성도 설계해야 한다.

따라서 1안은 구현과 설명이 단순한 초기 출시안으로 두고, Elo는 실제 과제별 응시·점수 데이터가 쌓인 뒤 비교 실험할 두 번째 안으로 권장한다. Elo를 적용해도 과제별 상세 점수와 복기 기능은 그대로 제공하고, Elo가 합산하는 범위와 산정 근거를 사용자에게 공개해야 한다.

## 5. 노출 정보와 개인정보

### 랭킹 목록

- 순위, 티어, 닉네임, 총점, 복기 횟수, 기록 갱신일을 표시한다.
- 세부 채점 리포트, 응시 대화, 작업 코드, 이메일, 실명은 공개하지 않는다.
- 본인은 랭킹에 참여하지 않아도 개인 점수·성장 화면을 이용할 수 있다.
- 비공개 사용자는 공개 참여자 기준의 본인 순위·백분위를 본인 화면에서만 볼 수 있다. 비공개 사용자의 닉네임·점수·프로필은 다른 사용자에게 노출하지 않는다.
- 닉네임은 회원가입 때 필수로 정하고, 현재 사용 중인 계정 사이에서 중복을 허용하지 않는다. 앞뒤 공백은 제거한 값으로 중복을 검사한다.
- 기존 계정은 랭킹에 참여하기 전에 고유 닉네임을 설정해야 한다. 중복 닉네임이 있으면 해당 사용자에게 변경을 안내한다.

### 계정 상태

- 탈퇴 계정은 공개 랭킹에서 제외한다. 기존 계정이 재활성화되면 기존 응시 기록을 유지하고, 해당 계정의 공개 설정에 따라 랭킹에 다시 포함한다.
- 랭킹 공개 설정을 끄면 목록과 사용자 검색에서 빠지게 한다. 캐시나 집계 자료에서도 정해진 시간 안에 반영되도록 한다.

## 6. 화면 초안

### 과제 상세 또는 결과 화면

- `과제 랭킹` 진입점
- 내 최고 점수와 현재 순위
- 내 첫 기록 대비 점수 변화와 최근 기록
- 랭킹 참여 설정

### 과제별 랭킹 화면

- 과제명 및 “자가진단 최고 기록” 안내
- 순위 / 티어 / 닉네임 / 점수 / 복기 횟수 / 갱신일
- 내 행 강조 및 내 순위로 이동
- 동점 공동 순위 표시
- 내 성장 상세로 이동하는 링크

모바일에서는 점수·순위·티어를 우선 노출하고, 복기 횟수와 갱신일은 보조 텍스트로 표시한다.

## 7. 백엔드·프론트 구현 방향

### 백엔드

- 기존 응시(`attempts`)와 리포트(`attempt_reports`)를 기반으로 과제별 최고 기록을 조회한다.
- `mode = 'SELF'`, 완료된 유효 리포트, 활성 계정, 공개 참여 동의를 적용한다.
- 사용자별 최고 기록을 먼저 고른 뒤 점수만으로 정렬하고 공동 순위를 계산한다. 풀이 시간은 조회·정렬 조건으로 사용하지 않는다.
- 점수 순위의 백분위로 티어를 부여하며, 동점 사용자가 티어 경계에 걸리면 같은 티어로 묶는다.
- 목록 API에는 공개 가능한 최소 정보만 반환한다. 상세 리포트나 응시 ID는 노출하지 않는다.
- 복기 분기 집계와 조회 비용을 실데이터로 확인한다. 트래픽이나 쿼리 비용이 커지면 집계/캐시를 추가하되, 원본 응시 기록에서 재생성 가능하게 설계한다.
- 공개 설정 저장, 동의 철회 반영, 탈퇴 계정 제외, 페이지네이션과 정렬의 일관성을 검토한다.
- 시즌별 결과 보관과 크레딧 지급 이력을 시즌 단위로 추적한다. 시즌 마감 후 결과 확정·보상 지급은 재시도되어도 중복되지 않게 처리한다.

### 프론트엔드

- 과제 목록/상세와 결과·복기 완료 흐름 중 랭킹 진입 위치를 정한다.
- 공개 설정의 의미와 노출 정보를 설명하고, 설정 상태를 명확하게 보여준다.
- 랭킹 목록, 내 기록 강조, 최고점 갱신 후 안내, 빈 상태와 비공개 상태를 설계한다.
- 랭킹 UI에서 기업 실전 과제나 기업 결과로 이동할 수 없도록 `SELF` 경로 안에 둔다.

## 8. 점진적 출시

1. **정책 반영:** 랭킹 공개 기본값, 최종 시즌 주기, 최고점 정책, 티어 분포, 복기 횟수, 탈퇴·재가입 기준을 구현 명세와 화면 문구에 반영한다.
2. **내부 검증:** 실제 응시 몇 건을 뽑아 수작업으로 시즌 랭킹과 티어를 계산하고 API 후보 결과와 대조한다. 구버전 리포트, 동점, 티어 경계, 롤백 분기 사례를 포함한다.
3. **제한 공개:** 기능 플래그 또는 소규모 사용자 공개로 잘못된 순위·티어, 공개 철회 반영을 확인한다.
4. **전체 공개:** 사용량과 문의를 확인하면서 노출 범위를 확대한다.

기존 배포판과 호환되도록 API를 추가하고, 기존 응시·채점 흐름에는 랭킹을 이유로 변경을 요구하지 않는다. 배포 전에 실제 운영 배포 커밋과 개발 브랜치 기준이 일치하는지 확인한다.

## 9. 성공 지표와 점검 항목

- 자가진단 완료 사용자 중 랭킹 참여 비율
- 랭킹을 본 사용자와 보지 않은 사용자의 재응시·점수 향상 비율
- 최고 기록 갱신 사용자 비율과 점수 상승 폭
- 시즌 재참여율, 과거 시즌·시즌 내 주차별 기록 열람률, 보상 크레딧의 지급량과 사용량
- 공개 설정 변경·철회 반영 시간 및 관련 문의
- 랭킹 API 응답 시간과 조회 오류율
- 특정 과제의 응시 횟수·복기 횟수 편중 여부

경쟁이 개인의 학습을 돕는지 평가하려면 순위 상승뿐 아니라 점수 향상과 재응시 후 학습 지속 여부를 함께 본다.

## 10. 정책 결정 현황

| 항목 | 결정 |
|---|---|
| 공개 참여 기본값 | 기본 비공개. 사용자가 명시적으로 참여를 켜야 공개 랭킹에 표시 |
| 표시 이름 | 회원가입 때 새 닉네임 설정. 현재 사용 중인 계정 간 중복 불가. 기존 계정은 랭킹 참여 전에 고유 닉네임 설정 |
| 랭킹 기록 | 사용자별·과제별 최고 유효 점수. 같은 최고 점수의 응시가 여러 개면 최근 완료 기록을 대표로 표시하되 순위에는 영향 없음 |
| 점수 구버전 | 유효한 100점 총점이 있는 완료 리포트만 포함 |
| 복기 횟수 | 사용자·과제별 롤백 분기 응시 수. 순위 계산에는 사용하지 않고 보조 정보로 표시 |
| 티어 | 챌린저·마스터·다이아몬드·플래티넘·골드·실버·브론즈. 제외 티어 비율을 빼고 남은 비율을 100%로 정규화 |
| 티어 비율 | 각각 0.01%, 1.12%, 5.02%, 22.43%, 28.14%, 25.03%, 18.25%. 동점은 분리하지 않으므로 실제 비율은 달라질 수 있음 |
| 비공개 사용자의 개인 순위 | 공개 참여자 기준 순위·백분위를 본인에게만 제공. 타인의 목록에는 표시하지 않음 |
| 탈퇴·재가입 | 탈퇴 계정은 공개 목록에서 제외. 기존 계정이 재활성화되는 경우 기존 응시 기록을 유지하므로 해당 계정의 공개 설정에 따라 다시 포함 |
| 순위 표기 | 총점 내림차순만 사용. 동점은 공동 순위. 풀이 시간은 랭킹에 사용하지 않음 |
| 시즌 초기화 | 2주 또는 3주마다 새 랭킹을 시작하는 방향. 초기에는 3주를 권장하며 최종 주기는 참여 규모를 보고 확정. 이전 시즌 응시 점수는 다음 시즌에 반영하지 않고 과거 결과는 조회 가능 |
| Elo 대안 | 과제 난이도를 보정해 여러 과제 결과를 시즌 종합 레이팅으로 합치는 두 번째 안. 파일럿 데이터가 쌓인 뒤 검증하며, 현재는 채택하지 않음 |

닉네임 중복 검사는 입력 앞뒤 공백을 제거한 값으로 한다. 대소문자 구분이 있는 문자 체계를 고려해 비교 규칙을 백엔드·DB에서 동일하게 적용한다. 랭킹 공개 설정을 끄면 공개 목록에서 빠지며, 개인 기록은 계속 볼 수 있다.

브랜치는 생성했으며 현재 체크아웃된 브랜치는 변경하지 않았다. 작업을 시작하기 전에 실제 운영 배포 SHA를 확인하고, 브랜치 기준점이 배포 기준과 다르면 필요한 최신 main 커밋을 반영한다.
