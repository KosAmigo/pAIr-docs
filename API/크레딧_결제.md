# 크레딧 테스트 결제

토스페이먼츠 테스트 키로만 결제를 승인한다. `PAIR_TOSS_SECRET_KEY`에 테스트 시크릿 키를 설정하고,
프론트에는 같은 키 세트의 테스트 클라이언트 키를 별도로 설정한다. 시크릿 키는 프론트·소스·로그에 넣지 않는다.
결제 화면은 프론트에서 토스페이먼츠 SDK로 구현해야 한다. 이 저장소에는 결제 화면이 없다.
개발 연동 체험 상점에서 사용할 수 있는 키 유형과 결제수단은
[토스 문서](https://docs.tosspayments.com/reference/using-api/api-keys)를 확인한다.

모든 API는 로그인한 사용자만 사용할 수 있다.

1. `GET /api/credits/products`로 상품을 확인한다.
2. `POST /api/credits/purchases`에 `{"credits":1000}`처럼 상품의 크레딧 수량을 보낸다.
   응답의 `orderId`, `amountKrw`, `credits`를 토스 결제 요청에 사용한다. 금액은 서버에서 결정한다.
3. 토스 인증 성공 URL에서 받은 `paymentKey`, `orderId`, `amount`를 사용해
   `POST /api/credits/purchases/{orderId}/confirm`에 `{"paymentKey":"...","amount":4990}`을 보낸다.
   인증 성공만으로는 적립되지 않는다. 서버가 토스 승인 결과의 주문·금액·상태를 검증한 다음 적립한다.
   토스 인증 후 10분 이내에 승인해야 한다.
4. 결제창을 닫거나 인증에 실패하면 `POST /api/credits/purchases/{orderId}/cancel`을 호출한다.
   승인 처리가 이미 시작된 주문은 이 API로 취소할 수 없다. 방치된 `READY` 주문은 24시간 후 만료된다.
5. 잔액은 `GET /api/credits`(`{"balance":190,"unlimited":false}`. 관리자는 `unlimited: true` 이고 크레딧 없이 자가진단을 쓴다), 구매 내역은 `GET /api/credits/purchases`,
   적립·사용 내역은 `GET /api/credits/ledger`에서 조회한다. 두 내역 API는 `page`(0부터)와
   `size`(1~100, 기본 20)를 받는다.

승인 응답이 불명확하면 `CONFIRMING`을 유지한다. 같은 주문번호·paymentKey·금액으로 승인 API를
다시 요청하거나 `POST /api/credits/purchases/{orderId}/recover`를 호출하면 동일한 멱등키를
사용하거나 토스 상태를 조회해 복구한다. 14일 이후에는 멱등키 만료를 고려해 토스 조회만 수행하므로,
미해결 건은 별도 확인이 필요하다. 가상계좌가 입금 대기인 경우 입금 이후에 복구 API를 호출해야 한다.
자동 웹훅 및 자동 재확인은 구현하지 않았다.

## 모의 환불

`POST /api/credits/purchases/{orderId}/refund`는 **토스 취소 API를 호출하지 않는다**.
현재 사용 가능 잔액이 해당 구매의 크레딧 이상일 때 DB에서 해당 크레딧을 회수하고 상태를
`REFUNDED`로 기록한다. 크레딧의 출처나 구매 후 사용 여부는 구분하지 않는다. 환불과 다른 차감은
회원 행 잠금으로 직렬화되며, 중복 요청은 한 번만 회수한다.

따라서 토스 테스트 결제 내역은 승인 완료로 남는다. 이는 금전 환불이 아닌 프로젝트용 시뮬레이션이다.
라이브 서비스에서는 실결제 취소, 장애 복구 및 별도의 환불 정책 구현이 필요하다.
