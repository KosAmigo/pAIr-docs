# 백엔드 패키지 구조와 이름 규칙

> 2026-11-23 확정. pAIr-back 코드는 이 규칙을 따른다. 어기면 빌드가 실패한다.

## 구조

```
com.pair
├─ PairApplication
├─ global/    config/ error/ security/            여러 기능이 같이 쓰는 것
├─ infra/     ai/ sandbox/ storage/ payment/ mail/ 외부 시스템 연결
└─ domain/<기능>/                                 업무 기능 (auth, exam, attempt …)
   ├─ controller/  service/  dto/
   └─ repository/  entity/   exception/
```

- 기능 폴더 안에는 위 6개 폴더만 쓰고, 필요한 것만 만든다. 기능 폴더 바로 아래에는 클래스를 두지 않는다.
- 새 기능은 `domain/<영어 소문자>/`로 추가한다. `global/`, `infra/`에 폴더를 새로 만들 때는 팀에서 정한다.

## 이름: 폴더 이름 = 끝말

폴더 안의 **모든 클래스**가 예외 없이 이 끝말을 쓴다(인터페이스, 도우미, 스케줄러 포함).

| 폴더 | 넣는 것 | 클래스 이름 |
| --- | --- | --- |
| `controller/` | API 입구 | `XxxController` |
| `service/` | 로직이 있는 클래스 전부 | `XxxService` |
| `dto/` | 데이터만 담는 클래스 | API는 `XxxRequest` / `XxxResponse`, 나머지는 `XxxDto` |
| `repository/` | DB 저장·조회 | `XxxRepository` |
| `entity/` | DB 테이블 (`@Table` 필수) | 끝말 없는 명사 (`Record`, `Entity` 금지) |
| `exception/` | 이 기능에서만 쓰는 예외 | `XxxException` |
| `global/config/` | 설정 | `XxxConfig` / `XxxProperties` |
| `global/error/` | 공통 예외와 예외 처리기 | `XxxException` / `XxxExceptionHandler` |

- 이름 앞부분은 하는 일을 단수 명사로 쓴다. `EditProposals`(X) → `EditProposalService`(O)
- 엔티티와 이름이 겹치는 데이터 클래스에는 `Dto`를 붙인다. 엔티티 `Attempt`, 데이터 `AttemptStateDto`
- 파일 하나에 클래스 하나. `XxxDtos` 같은 묶음 파일은 만들지 않는다.

## 어디에 두나

| 무엇 | 위치 |
| --- | --- |
| 한 기능에서만 쓰는 것 (메일, PDF, 스케줄러 포함) | 그 기능 폴더 |
| 여러 기능이 쓰는 예외 | `global/error/` |
| 외부 호출 실패 예외 | `infra/<분야>/` |
| 인터셉터, 리졸버, 인증 확인 | `global/security/` |
| 설정 클래스 | `global/config/` |
| 테스트 | main과 같은 패키지. `대상클래스Test` 또는 `시나리오Test` |

## 검사

`global/config/PackageRulesConfig`가 아래 세 곳에서 같은 검사를 돌린다.
- `./gradlew classes` / `build`: 빌드가 실패한다. IntelliJ ▶ 실행도 이 빌드를 먼저 거친다("Build and run using: Gradle", 기본값).
- 서버를 켤 때: 서버가 뜨지 않는다. 운영 서버에서만 `PACKAGE_RULES_ENABLED=false`로 끈다.
- `./gradlew test`: `ArchitectureTest`가 실패한다.

검사를 통과하려고 `PackageRulesConfig`를 고치지 않는다. 규칙에 안 맞는 클래스가 있으면 팀에서 정한다.

## 이렇게 정한 이유

- **기능별로 나눈 이유**: 계층별(맨 위가 controller/service)로 나누면 폴더 하나에 클래스가 수십 개 쌓인다. 기능 하나를 고칠 때도 여러 폴더를 오가야 한다.
- **안쪽 폴더를 고정한 이유**: 기능마다 모양이 달랐다(`exam`은 `domain/web`, `attempt`는 `db/`). 폴더를 고정하면 어느 기능을 열어도 같은 곳에서 같은 것을 찾는다.
- **`service`를 예외 없이 `Service`로 정한 이유**: 다른 프로젝트(SmartTicketing)에서 도우미 이름을 자유롭게 두었더니 `XxxRanks` 같은 애매한 이름이 늘었다. 이름이 조금 어색해도(`XlsxStyleService`) 규칙이 하나인 편이 사람과 AI 모두 지키기 쉽다.
