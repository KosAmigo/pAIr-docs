# 카메라 감독 설계

## 1. 한 줄 요약

- **웹캠 하나만** 쓴다. 응시자 PC 브라우저가 웹캠을 분석하고, 서버는 분석하지 않는다.
- 이벤트(경고)가 나면 **앞 8초·뒤 4초 웹캠 사진**을 올려 파일 저장소에 두고, 감독관·매니저가 **완료된 회차에서도** 확정/기각한다.
- **실시간 영상(웹캠·화면·휴대폰 3채널)은 전부 사용하지 않는다.** 휴대폰 보조 캠과 PC 화면 공유도 사용하지 않는다. 연속 녹화, 영상 스트리밍, 서버 추론도 하지 않는다.
- 탭 전환·창 이탈·마우스 이탈·전체 화면 해제·붙여넣기는 브라우저 이벤트로 감지해 응시자에게 경고하고, 감독관 콘솔에는 이력으로만 남긴다.

## 2. 구현 상태

| 구분 | 내용 | 상태 |
|---|---|---|
| 구현됨 | PC 웹캠 분석(얼굴·포즈, MediaPipe), 규칙 엔진, 이벤트 + 사진 업로드 | main |
| 구현됨 | 분석 Web Worker 분리(감독 루프·환경 점검), 환경 점검 성능 자가 측정 | 프론트 `main`, 실제 카메라 검증 전 |
| 구현됨 | 이벤트 증거 구간 업로드·조회(`/clip`), 콘솔 타임라인·완료 회차 검토 | 백엔드 `develop`(V24), 프론트 `main` |
| 구현됨 | 보관 연장(회차 단위, 삭제 2일 전부터 7일씩 최대 2번, 이력), 동의 문구 v2, 보관 기본 7일 | 백엔드 `develop`(V23), 프론트 `main` |
| 구현했으나 **사용 안 함** | 감독관 실시간 영상 보기(WebRTC P2P, 개발 릴레이·운영 시그널링), 휴대폰 JPEG 프레임 중계·분석 Worker, PC 화면 공유 | 코드와 스위치만 남김. 스위치 `LIVE_VIEW_ENABLED`(`PAIR_LIVE_VIEW_ENABLED`), `PHONE_CAM_ENABLED`, `SCREEN_SHARE_ENABLED` 는 전부 꺼진 상태가 정책 |
| 남은 일 | 코드 스위치 기본값을 정책에 맞춤(휴대폰 캠·화면 공유가 아직 `true`), 실제 카메라 확인, 오탐률 측정 | |

## 3. 구조

```
응시자 PC 웹캠 → 분석 Worker(MediaPipe) → 규칙 엔진 → 이벤트
   PC 로컬 링 버퍼(웹캠 프레임, 앞 8초) + 이벤트 후 4초 수집
        └─ 이벤트 후 약 5초 뒤 업로드 ─→ 서버/파일 저장소 ─→ 감독관·매니저 콘솔(타임라인, 확정/기각)
브라우저 이벤트(탭·창·마우스·전체 화면·붙여넣기) ─→ 서버 기록 ─→ 콘솔 이력 (확정/기각 없음)
```

### 3-1. 분석 (PC 브라우저)

- 웹캠 분석은 Web Worker 에서 돈다. Worker 가 안 되면 메인 스레드로 폴백한다(`VisionBackend` 구조).
- 규칙: 얼굴 없음, 여러 얼굴, 고개 돌림·숙임, 시선 이탈, 자리 이동, 몸 돌림 (`core/pcRules.ts`). 카메라 이벤트 세부 내용은 숫자 대신 문장으로 보여 준다.
- 느린 PC: 환경 점검에서 분석 속도를 재서 느리면 분석 간격을 늘린다.

### 3-2. 증거 구간

- 앞 8초 / 뒤 4초, 1초 간격으로 웹캠 사진을 최대 12장. PC 가 로컬 링 버퍼에 두었다가 이벤트가 나면 올린다(연속 업로드 없음). 업로드는 이벤트 후 약 5초 뒤.
- 파일은 DB 가 아니라 파일 저장소에, DB 에는 키와 이벤트 정보만 둔다. 요청 본문 2MB·사진 100KB 상한.
- API·테이블: [API §7](../API/실전시험_감독_API.md), [테이블 정의서](erd/테이블_정의서.md)(V23·V24, `proctor_event_frames`·`snapshot_retention_extensions`).

### 3-3. 검토와 보관

- 감독관·매니저가 완료된 회차에서 이벤트별 구간을 타임라인으로 보고 확정/기각한다(카메라 이벤트만). 모델은 선별만, 판단은 사람이다.
- 사진은 회차 종료 7일 뒤 삭제. 삭제 2일 전부터 **회차 단위**로 7일씩 최대 2번(총 21일) 연장하고, 누가 언제 연장했는지 이력을 남긴다. 연장은 종료된 회차만. 알림은 콘솔 표시만.
- 동의 문구: "7일 뒤 삭제, 최대 2번 연장 가능(총 21일)".

## 4. 실측 근거 요약 (자세한 내용·한계는 Worker 설계 문서)

| 항목 | 결과 | 한계 |
|---|---|---|
| 코어 제한 1코어(약 2.5배 느림) | 메인 방식 막힘 87%·9fps, Worker 1%·116fps (분석은 초당 3.7회로 느려짐) | 조건당 1회, 정지 얼굴 이미지 입력 |

## 5. 위험

- 분석이 응시자 PC 에서 이루어지므로 결과 조작 가능성이 남는다. 사람이 사진 구간을 보는 검토와 브라우저 이벤트 기록으로 줄이되 완전한 방어는 아니다.
- 실시간 영상을 쓰지 않으므로 감독관이 현장을 실시간으로 볼 수는 없다. 사후 사진 검토와 이벤트 이력으로 판단한다.
- 오탐률·데이터 절감률은 아직 실측하지 않았다(측정 도구 `FalsePositiveLab`, `lowspec-bench` 준비됨).

## 6. 폐기한 제안: 서버 GPU 추론 (정현, 2026-11-23)

앞캠·뒷캠을 모두 RunPod GPU 추론 서버가 분석하고 시험 전체를 녹화해 감독관이 나중에 검수하는 안이었다(YOLO·MediaPipe 서버 실행, 5초 조각 S3 업로드, 10명 이하 1차 구현). 분석을 PC 브라우저에 유지하고 연속 녹화를 하지 않는다는 방향이 확정되어 **채택하지 않았다.** 상세 내용은 git 이력의 이전 `카메라_감독_설계.md` 를 본다.
