# 카메라 감독 설계 (앞캠·뒷캠)

> 작성: 정현 · 2026-11-23
> 근거: [실전시험_감독_API.md](../API/실전시험_감독_API.md), pAIr-front `main`의 `src/proctor/`(relay/peerLink, relay/viewerSender, watch/ViewerSession, core/pcRules, core/phoneRules), pAIr-back `exam/service/`(ProctorService, S3SnapshotStorage, ExamScheduler)

## 1. 한 줄 요약

- **앞캠(응시자 PC 웹캠):** 얼굴이 보이는지, 다른 사람이 있는지, 고개·시선·몸을 돌리는지 감지합니다.
- **뒷캠(응시자 휴대폰):** **두 손이 보이는지**와 **정면 모니터 1대 말고 다른 전자기기가 있는지** 감지합니다. 시험 전체를 녹화해서 감독관이 나중에 검수할 수 있게 합니다.

- **분석 위치 (2026-11-23 결정):** 응시자 PC와 휴대폰은 **앞캠·뒷캠 모두** 분석하지 않습니다. **RunPod GPU에 띄운 추론 서버**가 분석하고, 위반 이벤트는 백엔드를 거쳐 감독관에게 전달됩니다.
- **목표:** 좋은 결과 + 최소 비용. GPU는 **시험 시간에만** 빌립니다.
- **전제:** 지금 구현은 동시 응시자 10명 이하를 가정합니다. GPU 1대로 충분하고, 인원이 많아졌을 때 바꿀 점은 [6장](#6-인원이-많아지면-확장-방식-구현하지-않음)에 적었습니다.

## 2. 지금 코드 상태 (pAIr-front `main`, 2026-11-23)

- **휴대폰 → 응시자 PC:** 휴대폰은 영상만 WebRTC로 PC에 보냅니다(최대 1.2Mbps·15fps, 책상 스캔 때 3.5Mbps).
- **분석:** 응시자 PC 브라우저가 MediaPipe로 두 카메라를 모두 분석하고, 위반 이벤트와 사진을 백엔드에 올립니다.
  - 앞캠: 얼굴, 자세 (`core/pcRules.ts`)
  - 뒷캠(휴대폰 영상): 손, efficientdet_lite0 물체 탐지 (`core/phoneRules.ts`)
- **응시자 PC → 감독관:** 감독관이 그 응시자를 열었을 때만 PC가 영상을 WebRTC로 다시 보냅니다. 영상은 서버를 지나지 않고 저장되지 않습니다.
- **연결 신호:** offer/answer/ICE는 relay WebSocket으로 주고받습니다.
  - 운영용 relay(Spring WebSocket)는 아직 없고, 개발용 relay(Vite 플러그인)만 있습니다.
- **ICE 서버:** 기본은 공개 STUN만 씁니다. 휴대폰과 PC의 네트워크가 다르거나 막힌 망이면 TURN이 필요합니다.
- **아직 없는 것:** 녹화 저장
- **이 문서로 바꾸는 이유:**
  - 판정이 응시자 PC에서 이루어져 결과를 조작할 수 있습니다.
  - MediaPipe 작은 모델은 손에 든 휴대폰을 잘 놓칩니다.

## 3. 1차 구현 구조 (10명 이하)

```
응시자 PC 앞캠 ──① 0.5초마다 JPEG(480px) + 임시 토큰──┐
휴대폰 뒷캠 ─────① 2초마다 JPEG(640px) + 임시 토큰────┴─▶ 추론 서버 (RunPod GPU, 시험 시간에만)
     │                                                     │ ② 판별 + 판정 규칙
     │                                                     └─③ 위반 이벤트 + 사진 ──▶ 백엔드 (서울 EC2)
     │                                                                                  │ ④ 저장 + 감독관에게 경고
     ├──⑤ 녹화 5초 조각 → S3(서울) 직접 업로드 (백엔드가 서명 주소 발급)
     └──⑥ 실시간 영상: 지금처럼 휴대폰 → PC → (감독관이 열 때만) 감독관
```

### 3-1. 휴대폰 (PhoneCamPage)

- **판별용 사진:** 2초마다 640px JPEG(약 40KB)를 추론 서버로 **직접** 보냅니다. 백엔드를 거치지 않아서 백엔드 부하와 AWS 송신 요금이 없습니다.
- **인증:** 휴대폰이 짝 연결될 때 백엔드가 발급한 **임시 토큰**(응시자 ID, 회차, 만료 시각을 담고 서명한 값)을 붙여 보냅니다.
- **녹화:** `MediaRecorder`로 640×360, 10fps, 약 250kbps 영상을 만들고, 5초 조각을 S3 서명 주소로 직접 올립니다.
  - 실패한 조각은 휴대폰에 잠깐 들고 있다가 다시 보냅니다.
  - iOS Safari는 mp4로만 녹화되므로 webm과 mp4를 둘 다 받습니다.
- **녹화 영상에서 프레임을 뽑지 않는 이유:** `MediaRecorder` 조각은 첫 조각 없이는 따로 열 수 없어서 서버에서 프레임을 뽑기 어렵습니다. 판별용 JPEG를 따로 보내는 쪽이 단순합니다.
- **실시간 영상:** 지금 구조(휴대폰 → PC WebRTC)를 그대로 둡니다. PC는 영상을 보여 주고 감독관에게 넘기기만 하고, 분석하지 않습니다.
- **화면 꺼짐 방지:** Wake Lock을 추가합니다.
- **휴대폰은 모델을 돌리지 않습니다.** JPEG 인코딩, 녹화, WebRTC 송신만 합니다.

### 3-2. 응시자 PC (앞캠)

- **분석 코드를 뺍니다.** MediaPipe 모델 로딩과 `pcRules`/`phoneRules` 판정을 응시자 PC에서 지웁니다.
- **판별용 사진:** 앞캠 화면을 **0.5초마다** 480px JPEG(약 25KB)로 추론 서버에 보냅니다.
  - 앞캠 규칙은 1~2.5초 지속을 보기 때문에 뒷캠(2초 간격)보다 자주 보냅니다.
  - 인증은 휴대폰과 같은 방식의 임시 토큰을 씁니다(응시자 입장 때 백엔드가 발급).
- **기준 자세 잡기:** 지금은 PC가 시작 직후 몇 초 동안 기준 자세를 잡습니다. 이제는 추론 서버가 응시자별로 처음 몇 초의 사진으로 기준을 잡습니다.
- **그대로 두는 것:**
  - 브라우저 이벤트(탭 이탈, 전체 화면 해제, 붙여넣기 등)는 PC에서만 알 수 있어서 지금처럼 PC가 백엔드에 보냅니다.
  - 화면 공유와 감독관에게 영상을 넘기는 기능
- **PC 부담이 줄어듭니다.** 모델을 안 돌려서 저사양 노트북에서도 시험 화면이 버벅이지 않습니다.

### 3-3. 추론 서버 (RunPod GPU, 새로 만듦)

- **기술:** Python(FastAPI) + ONNX Runtime GPU 하나로 만들고, Docker 이미지로 배포합니다.
- **GPU:** RunPod에서 가장 싼 급(RTX A4000/3090급) 1대입니다.
- **모델:**

  | 카메라 | 모델 | 실행 장치 | 용도 |
  | --- | --- | --- | --- |
  | 뒷캠 | YOLO 최신 **medium**(작성 시점 YOLO26m) | GPU | 휴대폰, 화면, 책, 사람 |
  | 뒷캠 | YOLO pose small | GPU | 손목 위치 |
  | 앞캠 | YOLO pose small | GPU | 몸 이동·몸 돌림 |
  | 앞캠 | MediaPipe Face Landmarker (Python) | 같은 Pod의 CPU | 얼굴 수, 고개 방향, 시선(눈동자 좌표) |

  - YOLO에는 고개 방향과 시선 기능이 없어서, 앞캠 얼굴은 지금 쓰는 MediaPipe Face Landmarker를 그대로 씁니다. 판정 기준값을 옮겨 오기도 쉽습니다.
  - Face Landmarker는 가벼워서 GPU 이득이 작으므로 Pod의 CPU에서 돌립니다.
- **부하 (10명):** 1초에 앞캠 20장 + 뒷캠 5장입니다. GPU 1대로 medium 모델을 돌려도 여유가 큽니다.
- **켜고 끄기:**
  - `ExamScheduler`가 RunPod API로 시험 10분 전에 Pod를 만들고, 시험이 끝나면 **삭제(terminate)**합니다.
  - 모델 파일은 Docker 이미지 안에 넣습니다. 그러면 Pod를 지워도 따로 보관할 디스크가 없어서, 꺼져 있는 동안 비용이 0입니다.
  - Pod 주소는 시작할 때마다 바뀝니다. 백엔드가 새 주소를 받아 토큰과 함께 PC·휴대폰에 알려 줍니다.
- **GPU 재고 대비:**
  - 시작 시각에 원하는 GPU가 없을 수 있어서 후보 GPU를 2~3개 둡니다.
  - 끝까지 못 구하면 같은 이미지를 **서울 EC2에서 CPU + 나노 모델**로 띄웁니다. 코드는 같고 설정만 다릅니다.
- **네트워크 지연:** RunPod는 해외 서버라 요청 한 번에 약 0.2초가 더 걸립니다. 0.5~2초 간격 판별이라 문제없습니다.
- **최신 사진 칸:** 응시자마다 최신 사진 1장만 둡니다. 밀리면 오래된 사진은 버리고 최신 것만 판별합니다.
- **묶음 처리:** 들어온 사진을 짧게(약 0.2초) 모아 한 번에 GPU에 넣습니다.
- **판정 규칙도 추론 서버에 둡니다.** 응시자별로 최근 판별 결과(연속 횟수)를 메모리에 들고 있다가 규칙을 넘으면 이벤트를 만듭니다.
- **사진은 저장하지 않습니다.** 위반 순간 사진만 이벤트와 함께 백엔드로 넘깁니다.
- **토큰 확인:** 백엔드와 같은 비밀 키로 서명을 확인합니다. 만료됐거나 회차가 끝난 토큰은 거절합니다.

### 3-4. 백엔드 (Spring, 서울 EC2)

- **임시 토큰 발급:** 응시자 입장 때(앞캠)와 휴대폰 짝 연결 때(뒷캠) 추론 서버용 토큰과 추론 서버 주소를 줍니다.
- **이벤트 수신:** 추론 서버 전용 내부 API로 이벤트와 사진을 받습니다(서비스 간 비밀 키 헤더).
  - 저장은 기존 `ProctorService`를 그대로 씁니다. 출처는 `PC_CAM` / `PHONE_CAM`입니다.
  - 응시자 PC가 올리는 `PC_CAM`·`PHONE_CAM` 이벤트는 받지 않도록 막습니다. 조작을 막기 위해서입니다. `BROWSER` 이벤트만 계속 받습니다.
- **감독관 전달:** 기존 감독관 이벤트 전달 경로(relay `watchRoom`)로 경고를 보냅니다.
- **녹화:** 조각 업로드용 S3 서명 주소를 발급합니다. 시험이 끝나면 조각들을 파일 하나로 합칩니다.
- **GPU 켜고 끄기:** `ExamScheduler`가 RunPod API로 Pod를 만들고 지웁니다. RunPod API 키는 백엔드 비밀 설정에만 둡니다.
- **추론 서버 상태 감시:** 추론 서버가 응답하지 않으면 감독관 화면에 "자동 감지 멈춤"을 표시합니다.

### 3-5. 판정 규칙 (기존 이벤트 이름 그대로)

**앞캠:** 지금 `core/pcRules.ts`의 규칙과 기준값을 Python으로 그대로 옮깁니다.

| 이벤트 | 조건 (지속 시간) |
| --- | --- |
| `NO_FACE` | 얼굴이 안 보임 (2초) |
| `MULTI_FACE` | 얼굴이 2개 이상 (1초) |
| `HEAD_TURN` | 고개를 화면 밖으로 돌림 (1.5초) |
| `HEAD_DOWN` | 고개를 오래 숙임 (5초) |
| `GAZE_AWAY` | 시선이 화면 밖 (2.5초) |
| `TORSO_SHIFT` | 자리에서 크게 움직임 (2초) |
| `TORSO_TURN` | 몸을 돌리거나 화면에서 멀어짐 (2초) |

**뒷캠:**

| 이벤트 | 조건 |
| --- | --- |
| `PHONE` | cell phone이 2번 연속(4초) 감지 |
| `EXTRA_SCREEN` | laptop + tv가 합쳐서 2개 이상, 2번 연속 |
| `HAND_MISSING` | pose의 손목 2개 중 하나라도 3번 연속(6초) 안 보임 |
| `BOOK` | book이 2번 연속 감지 |
| 사람 수 이상 | person이 0명이거나 2명 이상 (새 이벤트 추가 필요) |

- 기본 YOLO(COCO 데이터)에는 태블릿, 스마트워치, 이어폰, 손 클래스가 없습니다. 손은 pose의 손목으로 대신 판단합니다.
- 나머지 기기는 실제 뒷캠 사진으로 파인튜닝할 때 클래스를 추가합니다.

### 3-6. 감독관 콘솔

- **10칸 화면:** 응시자별 경고 상태를 보여 주고, 위반이 나오면 해당 칸에 경고를 표시합니다.
- **실시간 영상:** 칸을 열 때만 지금처럼 PC를 거쳐 WebRTC로 봅니다.
- **TURN:** 직접 운영하지 않고 Cloudflare TURN을 빌려 씁니다.
  - 휴대폰 → PC, PC → 감독관 두 연결 모두에 씁니다.
  - 백엔드가 Cloudflare API로 몇 분짜리 임시 접속 정보를 받아 나눠 줍니다. API 토큰은 백엔드 비밀 설정에만 둡니다.
- **시험 후 검수:** 녹화 영상에 위반 시점 표시를 달아서, 누르면 그 시간으로 바로 이동합니다.

### 3-7. 저장소: S3, 서울 리전 고정

- **AWS 리전은 서울(`ap-northeast-2`)로 고정합니다 (2026-11-23 결정).** S3 버킷, 백엔드(EC2), DB(RDS)를 모두 서울에 둡니다.
  - 같은 리전이라 서버 ↔ S3 전송이 무료입니다.
  - 응시자가 국내에 있어 응답이 빠릅니다.
  - 녹화 영상(개인정보)은 국외로 옮기지 않습니다.
- 추론 서버(RunPod)는 AWS 밖입니다. 판별용 사진만 잠깐 지나가고 저장되지 않습니다([7장](#7-개인정보) 참고).
- 이미 S3 코드가 있어서 새로 만들 것이 없습니다.
- 30일 뒤 자동 삭제 규칙을 겁니다.
- 검수 다운로드는 CloudFront(월 1TB 무료 전송)를 붙여 다운로드 요금을 없앱니다.
  - 버킷은 OAC로 비공개 유지
  - 백엔드가 CloudFront 서명 URL 발급

## 4. 비용

단가는 2026-11 기준 대략치입니다. 도입 전에 각 회사 가격표로 확인합니다.

**시험 1회 (10명 × 2시간):**

| 항목 | 비용 |
| --- | --- |
| RunPod GPU (시작 10분 전 ~ 종료, 약 2.5시간 × 시간당 $0.2~0.4) | **약 $0.5~1** |
| PC·휴대폰 → RunPod 사진 전송 (RunPod 수신은 무료, AWS를 거치지 않음) | $0 |
| 녹화 저장 (약 2.3GB) | 월 약 $0.06 |
| 업로드 요청 (5초 조각 약 1.4만 건) | 약 $0.07 |
| 검수 다운로드 (CloudFront) | $0 |
| TURN | $0 (무료 한도 안) |
| **합계** | **약 $1 안팎** |

**개발·테스트 기간:**
- 테스트할 때만 Pod를 켜고, 끝나면 반드시 지웁니다.
  - 예: 한 달 20시간 테스트 → 약 $4~8
- Pod를 지우지 않고 "정지"만 해 두면 디스크 보관 요금이 계속 붙습니다. 모델을 이미지에 넣고 **항상 삭제**합니다.
- RunPod는 선불 충전식이라 잔액 이상은 나가지 않습니다. 소액만 충전해 두면 실수로 켜 둬도 피해가 작습니다.

**데이터 사용량:**
- 응시자 휴대폰은 시간당 약 700MB를 업로드합니다.
  - 녹화 약 110MB
  - 판별용 사진 약 70MB
  - 실시간 영상(PC로) 약 500MB
  - 와이파이 사용을 안내합니다.
- 응시자 PC는 앞캠 사진으로 시간당 약 180MB를 업로드합니다.

## 5. 모델과 라이선스

- **YOLO26:** NMS가 없어서 후처리가 간단합니다. GPU라 medium 모델을 써서 작은 휴대폰도 더 잘 잡습니다.
- **라이선스:** Ultralytics YOLO는 **AGPL-3.0**입니다.
  - 교육·시연 프로젝트에서는 문제가 되지 않습니다.
  - 상업 서비스로 가면 유료 라이선스가 필요하거나, Apache-2.0 모델(D-FINE, YOLOX, RF-DETR 등)로 바꿔야 합니다.
- **정확도 개선:** 실제 뒷캠 사진 수백 장으로 파인튜닝하는 것이 가장 효과가 큽니다.

## 6. 인원이 많아지면: 확장 방식 (구현하지 않음)

동시 응시자가 많아지면(예: 100명, 감독관 1명당 10명) 앞캠·뒷캠을 합쳐 1초에 사진 약 250장이 들어옵니다.

| 항목 | 1차 (10명 이하) | 확장 (많은 인원) |
| --- | --- | --- |
| GPU | 가장 싼 급 1대 | 1대로 먼저 실측, 모자라면 한 단계 위 GPU 또는 Pod 2대 |
| 앞캠 얼굴 모델 | Pod CPU | Pod CPU 코어를 늘리거나, 앞캠 판별 간격을 1초로 늘림 |
| 응시자 배정 | 1대가 전부 | Pod가 여러 대면 백엔드가 회차·응시자별로 Pod 주소를 나눠 줌 |
| 예상 비용 (2시간 1회) | 약 $0.5~1 | 약 $1~3 |

- 판정 규칙이 응시자별 메모리 상태를 쓰므로, Pod가 여러 대일 때 한 응시자는 항상 같은 Pod로 보내야 합니다.

## 7. 개인정보

- 판별용 사진(앞캠은 **얼굴 사진**)이 해외 업체(RunPod) 서버로 갑니다. 개인정보보호법상 국외 이전에 해당할 수 있습니다.
  - 동의 문구(`ProctorConsent`)에 "국외(이전 국가, 업체명) GPU 서버에서 사진 분석, 저장하지 않음"을 넣습니다.
  - RunPod에 아시아·한국 데이터센터가 있는지 확인하고, 있으면 그 지역을 고릅니다.
- 추론 서버는 사진을 디스크에 쓰지 않고 메모리에서만 처리합니다.
- 녹화 영상과 위반 사진은 서울 S3에만 둡니다.

## 8. 정하지 않은 것

- 앞캠도 녹화할지. 지금은 뒷캠만 녹화합니다.
- 앞캠 판별 간격(0.5초)이 기존 규칙의 정확도를 유지하는지 실측
- 사람 수 이상 이벤트 이름과 심각도
- 녹화 조각 합치기를 시험 직후 할지, 검수할 때 할지
- 실전 시험 흐름은 팀원 4 담당이라, 프런트(PC 분석 제거)와 백엔드 작업 범위는 구현 전에 맞춥니다.
