# 과제 생성 파이프라인

> 작성일: 2026-11-24
> 좋은 과제의 기준은 [좋은_과제_기준.md](좋은_과제_기준.md)(E·M·Q 번호), 저장·API·폼은 [AI_과제_생성_설계.md](AI_과제_생성_설계.md)를 따른다. 이 문서는 **어떻게 생성하는지**만 정한다.

## 1. 목표

관리자에게 넘어가는 과제 중 **그대로 쓸 수 있는 비율 97% 이상**. 판정은 기준 문서 번호로 한다.

## 2. 지금 방식과 문제 (2026-11-24, 수율 73%)

한 번의 호출이 과제 전체(설명, 자료, 코드, 테스트, 정답, 문항)를 쓰고, 검사에 실패하면 처음부터 다시 쓴다.

| 반복 실패 | 원인 |
| --- | --- |
| 답 노출(M5) | 결함을 아는 모델이 자료도 쓴다. 설명하려는 경향을 금지 문장으로만 막는다 |
| 근거 없는 판단 지점(M4) | 판단 지점은 메타 정보로, 자료는 따로 써서 서로 어긋난다 |
| 숫자 모순(M1) | 숫자를 글로 지어내고 정합성 장치가 없다 |
| 고치면 다른 데서 샘 | 실패 시 통째로 다시 쓴다. 금지 규칙이 계속 늘어난다 |

## 3. 새 방식: 5단계

| 단계 | 입력 | 출력 | 아는 것 |
| --- | --- | --- | --- |
| 1. 설계도 | 폼(직군, 시간, 주제) | 시나리오, 숨은 결함(무엇, 어디, 무엇이 잡나), 판단 지점과 선택지별 근거 사실, 사실 목록, 숫자표(BIZ), 입력→기대 출력 예 목록 | 전부 |
| 2. 작성 | 설계도의 **사실 목록·예 목록** | 응시자에게 보이는 글: 설명, 요구사항, NOTES, 문서·CSV | 결함이 무엇인지 **모름** |
| 2'. 코드 (DEV) | 설계도 | 시작 코드(결함 포함), 공개 테스트 | 결함을 앎. 주석·글은 쓰지 않음 |
| 3. 정답 쪽 | 설계도 + 완성된 2·2' | 숨은 테스트, 정답, 다른 풀이, 오답, 문항·인정 답, 채점표, 후속 질문 | 전부 |
| 4. 검수 | 완성된 과제 전체 | 항목별 판정(E1~E5, M1~M5)과 위반 문장 인용 | 전부 |
| 5. 부분 수정 | 4의 지적 | 지적된 문장·파일만 고친 과제 → 4로 | 전부 |

**정보 가리기 (핵심):** 2단계는 결함 사실을 다른 사실과 구분 없이 섞인 목록으로 받는다. 모르는 함정은 설명할 수 없으므로 답 노출(M5)을 구조로 막는다. 판단 지점의 근거 사실도 이 목록에 들어가므로 자료에 반드시 들어간다(M4).

**숫자 (BIZ):** 숫자는 1단계 숫자표에만 정한다. CSV는 숫자표에서 만들고, 문서는 숫자표 값만 쓴다. 코드가 숫자표 정합성(부분 ≤ 전체, 합계)과 자료 속 숫자가 숫자표와 같은지 확인한다(M1).

## 4. 검사

| 종류 | 어디서 | 예 |
| --- | --- | --- |
| 실행·계산 검사 | 코드, 3단계 뒤 | 컴파일, 숨은 테스트가 시작 코드·오답에서 실패, 정답·다른 풀이 통과, 단답형 검산, CSV 형식, 숫자표 대조 |
| 의미 검사 | 4단계 검수(강한 모델, 판정표 기준) | 답 노출, 판단 근거, 숨은 결함이 드러났는지, 풀 수 있는지 |

- 오탐이 잦던 정규식·싼 모델 의미 검사는 4단계 검수로 옮기고 뺀다.
- 실패 처리: 부분 수정 최대 2번 → 그래도 실패하면 1단계부터 새로(최대 2번) → 끝내 실패하면 실패 표시와 함께 검수 전(HIDDEN)으로 저장.

## 5. 프롬프트 원칙

- 단계마다 짧게. 금지 목록 대신 "이렇게 쓴다"는 규칙.
- 검증에서 '그대로 사용' 판정을 받은 과제를 좋은 예로 1개씩 보여 준다.
- 모델·추론 강도는 단계별로 따로 정한다(초기값: 설계도만 terra high, 나머지는 terra medium 이하, 검수는 실행 검사를 통과한 과제에만). 비싼 모델은 비교 실험에서 효과가 확인될 때만 쓴다.

## 6. 확인 방법

- 독립 감사: 생성기 밖의 검증 세션이 판정표(기준 문서 번호별 통과·위반 예, 정현 로컬 `taskgen-runs/_verify/`)로 판정한다. 결함을 심은 과제를 섞어 감사 자체도 확인한다.
- 개수: 6개(직군 2 × 난이도 3)로 방향 확인 → 12개 → 30개로 97% 확인.
- 비용·시간 목표: 과제당 $0.3 이하, 10분 이하. 단계마다 토큰을 기록해 넘으면 줄인다.

## 7. 구현 순서

1. 1~3단계(설계도, 정보를 가린 작성, 정답 쪽)
2. 6개 검증
3. 4~5단계(검수, 부분 수정), 의미 검사 정리
4. 12개 → 30개 검증

## 8. 아직 정하지 않은 것

- 난이도: AI 단독 풀이가 숨은 결함을 잡으면 설계도를 다시 쓸지(지금은 참고 지표). 정하면 기준 문서부터 고친다.
