# 프런트 상태관리

pAIr-front 에서 데이터를 어디에 두는지 정한 규칙. (2026-11-28 정리)

## 어디에 두나

| 데이터 | 도구 | 위치 |
| --- | --- | --- |
| 서버에서 받는 데이터 (목록·상세·리포트·생성 작업 등) | React Query | `src/data/*` 쿼리 옵션 + `queryKeys.ts` |
| 여러 화면이 같이 쓰는 클라이언트 값 (크레딧 잔액) | Zustand | `src/data/credits.ts` |
| 로그인 정보 | Context | `src/auth/AuthProvider.tsx` |
| 한 화면 안에서만 쓰는 값 (입력값, 열림/닫힘, 시험 화면) | `useState` / 화면 훅 | 각 화면·`src/exam/hooks/` |

## React Query

- 공용 클라이언트: `src/queryClient.ts` (`staleTime 10초`, `retry 1`, 창 포커스 시 재조회 안 함)
- 쿼리 키는 `src/data/queryKeys.ts` 한 곳에 모은다. 같은 API 는 어느 화면이든 같은 키.
- 쿼리 옵션(키+함수)은 `src/data/` 에 객체로 두고 화면은 `useQuery(xxxQuery(...))` 만 부른다. 예: `userQueries.ts`, `consoleTasks.ts`.
- 사용자 화면 데이터는 `freshOnMount`(`staleTime 0, gcTime 0`): 열 때마다 새로 받고 떠나면 버린다.
- 폴링은 `refetchInterval`(함수로 조건부), 백그라운드 탭에선 멈춤(`refetchIntervalInBackground: false`). 예: 채점 중 리포트, 생성 작업 목록(`useGenJobs.ts`).
- 바꾼 뒤 반영: `invalidateQueries` 로 다시 받거나 `setQueryData` 로 캐시를 직접 고친다.
- 로그인 사용자가 바뀌거나 로그아웃하면 `queryClient.clear()` (`AuthProvider` + `auth/sessionChange.ts`). 다른 계정에 이전 데이터가 안 보인다.
- 로그인 헤더가 필요한 이미지는 Blob 쿼리(`queryKeys.blob`, `data/blobUrl.ts`).

## Zustand (크레딧)

- `createCreditStore(token)` 으로 로그인 토큰마다 store 를 새로 만들고 `CreditProvider` 가 Context 로 내려준다. 토큰이 바뀌면 store 도 바뀐다.
- 화면은 `useCredits()` 로 `{ state, refresh }` 만 쓴다. AI 채팅·구매 뒤 `refresh()`.
- 늦게 온 응답(이전 요청, 이전 토큰)은 버린다.

## 일부러 안 쓴 곳

- **로그인**: 거의 안 바뀌어서 Context 로 충분.
- **시험 화면(`RealExam`)**: 응시마다 상태가 따로라 화면 안 훅으로 둔다. `key={sessionId}` 로 응시가 바뀌면 통째로 새로 만든다. 문제 로드(`useExamLoader`)도 같은 이유로 직접 호출.
- **저장·채팅 전송·제출 같은 버튼 요청**: 직접 호출 후 필요한 쿼리만 invalidate.
- 편집기 입력이 버벅이면 그때 `memo` 분리나 React Compiler 를 검토한다.

## 테스트

- e2e 는 `e2e/mock.ts` 가 `/api/` 를 가로챈다(실제 백엔드·AI·크레딧 안 씀).
- 관련 e2e: `session-switch`(계정 바뀌면 캐시 비움), `task-generating`(폴링 간격), `self-exam`(채팅 뒤 크레딧 갱신).
